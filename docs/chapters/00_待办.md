## ✅ 已修：P4 提示档不再泄露答案（2026-11-07 Frank 定案）

> **Frank 原话（发现问题时）：**
> 「工具提示那个输入什么值输出什么值，绝对不能出现在明面上，
> 如果有标记为要改的地方，以及在哪个地方的哪段代码，
> **因为这相当于把答案放出来了。**」

### 一、问题（已解决，留档说明为什么原来的做法不对）

**原来的 P4 直接把 `(a, b)` 两个数摆出来：**

```
[T01] 数值变换工具
  示例：输入 2.5 → 输出 0.999999     ⚠️ 两个数都给了
```

**为什么这是泄露：**

```
给出 (2.5, 0.999999) 这样的输入输出对
        ↓
模型不用读描述，拟合两点就能反推函数身份
        ↓
⭐ 测的是「从数据反推函数」，不是「读懂描述」
```

**⭐ 这与本基准要测的能力（识别工具能不能用）不是一回事。**

### 二、Frank 的定案

> 「选用无关变量随机一个有效值替代，但更稳妥的做法是用 **ab 替代**，
> 输入 a 可以得到 b，**我猜你在那个式子里写了函数是什么吧？**
> **所以模型自己会判断输出什么。**
> 我们只需要提供 **a= 和 b= 的位置**，让模型输入 a 值 b 就会出来，
> 面板上在每个输入结束后会**按顺序保存下模型用过的记录**，以供后续出分析。」

**⭐ Frank 猜对了 —— 描述里确实写了函数是什么。实证：**

```
erf  → 本工具对（造型）的值执行如下变换：求一个数的误差函数值。
pow4 → 本工具对（造型）的值执行如下变换：求一个数自乘四次的结果。
```

**所以模型能从描述推出 b —— 这正是 P4 要测的能力。**

### 三、改成了什么

| 项 | 改前 | 改后 |
|---|---|---|
| **显示内容** | `示例：输入 2.5 → 输出 0.999999` | `输入 a = ?` / `输出 b = ?` |
| **给了什么** | 两个具体的数 | **只有两个位置，一个数都不给** |
| **b 从哪来** | 预先算好摆在明面上 | `toolconsole.call()` 当场算出来 |
| **测什么** | 从数据反推函数 | **读懂描述、自己判断输出什么** |

**模型看到的实际样子（T01，英文皮）：**

```
[T01] value transformer
  输入 a = ?   （manifestation）
  输出 b = ?   （loop，由工具算出）
```

**模型输入后：**

```
call(T01, 0.5)    →  输入 manifestation = 0.5     输出 loop = 0.5204998778
call(T01, -1.25)  →  输入 manifestation = -1.25   输出 loop = -0.9229001283
```

### 五、面板按顺序保存记录（Frank 要求的后半句）

**`ToolConsole` 已经做到了，2026-11-07 实测验证：**

```

    ↓

## ✅ 「组」的定义 —— 已定，不是待办（2026-11-07 Frank）

**Frank：**
> 「组就是每个链节自己内部的运算，我都明说的事情为什么能成为一个待办？」

**⚠️ 开发助手把这个当成了待确认项，是错的。定义早就说过了。**

**定义：**

```
「组」= 一条链上**每一个链节自己内部的那次运算**
        第 1 节一组、第 2 节一组…… 每节各成一组
```

**⚠️ 不是这些（曾经的错误理解，作废）：**
- ❌ 「40 个干扰选项分 10 组」
- ❌ 「一个选项的完整计算链」
- ❌ 「一个选项 + 它的近邻变体」

**⚠️ 与 `groupmap.py` 的「组」不是一回事，别混：**
`groupmap.py` 的 `group_id` 是**一道题内的变量名词映射**（编号 → 中文/英文名词），
是显示层的事；这里的「组」是**链节内部运算**，是数学结构的事。**两者无关。**

## （原）图片题面规格 —— `figures.py`，2026-11-07 Frank 定

**Frank 原话：**
> 「最后我们要组装图片上去，我的建议是**黑白图片**，
> 目的只是**考察模型的识别能力**。
> 要么**白底黑图像**要么**黑底白图像**，
> 在上面可以有**抽象的简单图案**，比如**几何大象、三角形**，
> **每个图片替换一个对象，就相当于绑定了固定代码**，
> 那么所选的图像也是**随机出来的**，绑定这个代码，
> 比如**一张白底图片上，有五只黑色大象**，
> 下面会用字写，**有几只大象**，用**清晰的大号字体**显示，
> 确保**图像和图像，图像和文字中间没有重叠遮罩**。」

**六条硬规格全部落实：**

| # | 规格 | 实现 |
|---|---|---|
| ① | **黑白** | 像素级验证只有两色（阈值化文字，无抗锯齿灰阶） |
| ② | **两种配色随机** | `light` 白底黑图 / `dark` 黑底白图，随机抽 |
| ③ | **抽象几何图案** | 11 种：大象/三角形/正方形/圆/十字/菱形/五角星/圆环/箭头/房子/回字 |
| ④ | **图案↔代码绑定** | 每道题随机抽一个图案，抽到即绑定（`Glyph`） |
| ⑤ | **大号字体问句** | 字号自动撑满（实测 ≥ 40px），中英双版，量词正确 |
| ⑥ | **零重叠** | **版面结构保证 + 像素级验证**：图区/空白带/文字带三段分离，空白带必须 0 像素 |

**实测渲染（1280×720）：**

- 白底五只大象 → 大象清晰可辨（身体/头/耳/鼻/四腿分离）
- 黑底三只大象英文 → `How many elephants are there?`
- 白底七只三角形 → `有几个三角形？`
- 黑底十二只圆 → 网格排布不重叠
- 白底二十只星 → 20 个仍可数

**⚠️ 踩过的坑（已修）：**
1. **文字抗锯齿出灰阶** → 文字画在单独一层，阈值化后硬贴合，才是真黑白
2. **大象造型画坏**（象鼻压在第四条腿上，像乱线）→ 重排部位坐标，各自不碰
3. **量词错**（「有几只三角形」「有几只房子」不通）→ 按图案配量词，大象用「只」、几何用「个」、房子用「座」
4. **英文复数** `cross` → `crosses` 特例已处理

**⚠️ 新增依赖：`Pillow 13.0.0`**（从清华镜像装）
