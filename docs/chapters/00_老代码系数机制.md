# 老代码的系数机制 —— 读懂了什么，怎么用到新结构

> **弗兰克 2026-11-08：「重点看他的系数什么情况下运作，
>  首先是你要理解他的情况和工况，最后是你要结合自己的情况去设置，
>  老代码会为你提供参考。」**

---

## 一、老代码的工况（它当时要解决什么）

```
老结构：10 节【嵌套复合】，只有起点 y 是给的
        y₀ → y₁ → y₂ → … → y₁₀

⚠️ 全部值都要现算，中间量一个都没有
```

**这就决定了它的核心矛盾：**

```
每一层算出来的 raw = f(v)·c，量级完全不受控。
可能 1e-20，也可能 1e+20。
直接喂给下一层 → 下一层要么吃不下（出 search），要么溢出。
```

**⇒ 所以它必须有一个东西，能把 raw「搬」到下一层能吃的位置。那就是 `cn`。**

---

## 二、老代码的三种工况，以及系数怎么运作

### 工况 1：cn 在打包时定死 —— ❌ 失败

```
做法：整批样本共用一个 cn，打包时决定
结果：2+2 复合 0/6 通过
原因：层间值域没人管
```

**⚠️ 为什么必然失败：**

```
一个乘数只能【整体平移】所有样本的量级，
但样本之间的【跨度】它压不了。

实测：n=1  跨度 1 倍    → 能塞
      n=10 跨度 435 倍  → 能塞
      n=20 跨度 440 倍  → 塞不进
```

**⇒ 结论：`cn` 不能是批级常数，必须是逐样本的。**

### 工况 2：cn 正向反向各算各的 —— ❌ 失败

```
做法：正向按输入现算一个 cn，反向按另一个输入再算一个
结果：通过率 43.2%
原因：正向得 10、反向得 100，不抵消
```

**⚠️ 为什么必然失败：**

```
正向：  t_k = f(t_{k-1}) · cn_正
反向：  t_{k-1} = f⁻¹(t_k / cn_反)

cn_正 ≠ cn_反 ⇒ 除不掉 ⇒ 值偏掉 ⇒ 越走越错
```

**⇒ 结论：`cn` 一旦定了就必须【正逆共用同一个数】，不能重算。**

### 工况 3：每步现算 + 正向记账、反向照抄 —— ✅ 成功

```
正向走一遍：每步现算 cn，记进【系数表】cm[层, 样本]
反向走一遍：按同一张表取 cn，除回来
```

**⚠️ 为什么这两件事不矛盾（老代码原话）：**

> 「cn 是「这一步 × 这一批样本」的属性，
>  正向走完它就定了，反向拿的是同一个数。」

**⇒ 这就是老代码的核心结论。已落到新代码里（`LinkPack.layers[].cn`）。**

## 三、⭐ 目标区间：老代码修过一次的错

```
❌ 错：cn 让本层输出落进【下一层的 y_range】
✅ 对：cn 让本层输出落进【下一层的 search】
```

**老代码原话（2026-11-06 21:24）：**

> 「原来用 nxt.y_range 是错的。y_range 是「输出区间」，不是「输入区间」。」

**⚠️ 这两个区间完全不同：**

| 区间 | 含义 | 谁在用 |
|---|---|---|
| `search` | 这个函数**能接受的输入** | ← `cn` 要让下游落进这里 |
| `y_range` | 这个函数**能产出的输出** | ← 最后一层要落进这里 |

## 四、⭐ 我这版漏掉的那个函数：`acceptable_input`

**老代码里有个函数我当时没抄：**

```python
def acceptable_input(pack, out_lo, out_hi, grid=4096):
    """
    如果【下一层】只能接 [out_lo, out_hi] 的值，
    这【一层】的输入该落在哪。
    """
    xs = linspace(pack.search)          # 在这一层的 search 上密网格
    ys = pack._fwd(xs) * pack.c         # 每一点能产出什么
    m  = (ys >= out_lo) & (ys <= out_hi)  # 哪些点的产出能被下一层接住
    return (xs[m].min(), xs[m].max())     # 取外包络
```

**它解决的是「反向推不动」的问题：**

```
老代码是正向走：给定 v，算 raw，挑 cn 让 raw·cn 落进下一层 search
               → 只要 cn 挑得到，就一定接得上

⚠️ 但我的是【反向走】：给定 y，倒推 v
               → v 是算出来的，我控制不了它落在哪
               → 可能落在下一层 search 之外 ⇒ 断
```

**⚠️ 这正是体检里 55% 失败的全部原因：**

```
acosh:  定义域 [1.01, 20]，实际 1          ← 卡在下边界
sqrt:   定义域 [0.01, 100]，实际 5.99e-05  ← 差 3 个数量级
expm1:  定义域 [0.01, 9]，  实际 0.0276
pow2:   定义域 [0.01, 100]，实际 0.0926
```

**⇒ 所以倒推时，`cn` 不能只保证「能反推回来」，
  还要保证「反推出来的值能落在上一层能接受的范围里」。**

## 五、⚠️ 新结构和老结构的关键差别（不能照抄的地方）

| | 老结构 | 新结构 |
|---|---|---|
| 方向 | **正向**：y 给定，往上推 | **反向**：y 给定，往下倒推 |
| 中间量 | 全部现算 | 只有 y 给定，x 是倒推的 |
| 层数 | 10 节嵌套 | 每节 2 层 |
| 谁受约束 | 正向输出要落进下一层 | **反推值要落进上一层能接受的范围** |

**⚠️ 方向反了，约束也就反了：**

```
老代码：cn 控制【输出】→ 让它落进下游 search
新代码：cn 控制【输入】→ 让它落进自己的 search
        （因为倒推时，反推出来的 v 就是这一层的输入）
```

## 六、新结构应该怎么设（结合上面）

### 倒推一层时，`cn` 要同时满足三条

```
给定   v_k（这一层的输出，已知或上一层倒推得到的）
要定   cn，然后算  v_{k-1} = f_k⁻¹( v_k / cn / c )

① 可反推     v_k / cn / c 必须落在 f_k 的【值域】里
              （否则 f⁻¹ 无解）

② 反推值得当 f_k⁻¹ 算出来的 v_{k-1} 必须落在
              【这一层自己的 search】内，且离端点 > 2%
              （否则下一轮倒推会出域）

③ 量级可控     v_{k-1} 不能在 1e-287 这种荒唐量级
              （体检发现 x 跨了 436 个数量级）
```

### 实操：不能先挑 cn 再算，要「先算再验，不成就换」

```
❌ 旧做法：挑一个 cn → 算 v → 不管 v 落在哪
✅ 新做法：枚举 cn 候选 → 每个都算一遍 v → 
           只保留「v 落在 search 内 且 量级可控」的
           → 都没有就换一组函数重来
```

**⚠️ 这正好和 GPU 的批量写法契合：cn 候选 × 样本，一次算完，用掩码筛。**

## 七、⭐ 为什么不能直接控制 x 的量级（2026-11-08 弗兰克纠正）

> 「我们现在控制不了 x 的量级，也没法控制，因为我们这的 x 是 y 生成的。
>  老代码里互相嵌套，自变量是上一步的因变量，
>  它那个等于**控制整个链条的初始值来放缩**，
>  我们这是通过**具体的链接内 y 来控制**，
>  如果真的要控制，也是**控制 y 的取值范围**。」

**⚠️ 我上一版写「加 CHAIN_X_MIN/MAX 硬约束」，判错了。已改。**

### 两种结构的根本差别

```
┌─ 老结构 ──────────────────────────────────────────┐
│  y₀(链头) → y₁ → y₂ → … → y₁₀                     │
│                                                    │
│  自变量 = 上一步的因变量                            │
│  ⇒ 整条链是一个【连通的量级传递】                    │
│  ⇒ 控制 y₀ 一个数，就能定住整条链的量级              │
│     然后每层用 cn 微调                                │
└────────────────────────────────────────────────────┘

┌─ 新结构 ──────────────────────────────────────────┐
│  链节 L001:  y₁ →(倒推)→ x₁                       │
│  链节 L002:  y₂ →(倒推)→ x₂      每节【各自独立】   │
│      ⋮                                             │
│  A000 × y₁ × … × y₁₀ = Z                          │
│                                                    │
│  x 是 y 的【副产物】，只在链节内存在                  │
│  ⇒ 节与节之间的 x 没有任何关系                       │
│  ⇒ x 的量级由 (y, cn, 函数) 三者共同决定             │
│     ⚠️ 但它【不是可独立设定的自由度】                │
└────────────────────────────────────────────────────┘
```

### ⭐ 结论：要控制就控制 y

**弗兰克的原话：「如果真的要控制，也是控制 y 的取值范围。」**

```
x = f⁻¹( y / cn / c )

能调的只有：
  y     ← ✅ 题面允许控制的量（就是选它当题目的数）
  cn    ← ⚠️ 只在「能反推 + 反推值在 search 内」允许的范围内挑
  f, c  ← ❌ 固定，不能动

⇒ 想控制 x 的量级，唯一的合法途径是控制 y。
   给 x 设上下界再硬卡，等于在改 y —— 那是改题，不是控制。
```

**⚠️ 所以「x 跨 436 个数量级」这件事的正确读法是：**

```
不是「x 需要被限制」
而是「某个 y 配上这组函数，倒推出来的 x 天生就那么大」

⇒ 处理方式：这一节【换一组函数重试】，
   而不是把 x 拉回来。换组合换不动，说明这个 y 不适合进链节。
```

**⚠️ 而 y 的取值范围已经在核心配置里了（`CHAIN_Y_LO/HI/DECADES`），
   要调节 x 的量级，就调那里，不新增 x 的界。**
