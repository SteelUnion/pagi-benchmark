## 二、核心论证链（判据②的根）

### 2.1 通用性 → 必须自主认知工具

**Frank 原话（2026-11-05）：**

> 「通用必须具备跨场景能力，而且 agi 本身就需要覆盖多场景，
> 因而不能只依赖 kv 缓存中人的提示，而是要学会认知并使用工具，
> 这项能力因此在 agi 基准测试中成为必测指标。」

**论证结构：**

```
通用 = 必须跨场景
      ↓
场景无限，不可能全部预置
      ↓
不能靠「人预先告知每个场景该用什么」
      ↓
必须自己认知、自己使用工具
      ↓
这是必测指标（不是性能优化，是准入）
```

**⭐ 关键：这是从「定义」推出来的，不是从「工程限制」推出来的。**

**对比前一版（被否掉的）：**

| 版本 | 推理起点 | 问题 |
|---|---|---|
| v1 | 上下文窗口有限 | 审稿人可说「上下文会变长」 |
| **v2（采用）** | **通用性定义本身** | **通用性的要求不随技术进步消失** |

### 2.2 中转站问路（Frank 的比喻）

**原话：**

> 「就好比 agi 在前往工作区域的途中必须经过中转站，而其记忆有限要问路一样，
> 起码我上来就告诉你了专家会什么，你要知道生活场景里可是一点提示都没有啊」

**映射：**

| 比喻 | 测试设计 |
|---|---|
| 必经中转站 | **必须调用工具才能到达答案，不可跳过** |
| 记忆有限 | 上下文装不下所有工具 |
| 要问路 | 必须主动识别并调用工具 |
| 对方自我介绍 | 工具给行为描述，不给完整规格 |

## 三、工具怎么给（核心设计）

### 3.1 三层信息结构

**Frank 的鸡兔同笼例子（原话）：**

> 「小华：『我住在农家大院里，每天最喜欢干的事情就是数动物的脚，可以打发时间，
> 你看，X 只鸡和 Y 只兔加在一起刚好是多少只脚，
> 我知道为什么，你遇到了这种复杂情况会算吗？』」

**这段里有什么 / 没有什么：**

| 有 | 没有 |
|---|---|
| ✅ 场景线索（农家大院、数脚） | ❌ 公式 |
| ✅ 能力暗示（我知道为什么） | ❌ 答案 |
| ✅ 提问姿态（你会算吗） | ❌ 「鸡兔同笼」这个术语 |

**⭐ 这是「自我介绍」，不是「操作手册」。**

### 3.2 绝对不能给的

**Frank 原话：**

> 「不能明说是鸡兔同笼，就像一个人不受教育，他拿到扳手不知道是干嘛的一样」

| ❌ 禁止 | ✅ 可以 |
|---|---|
| 「鸡兔同笼专家」 | 「我住在农家大院，爱数动物的脚」 |
| 「这是求解器，用于线性方程组」 | 「输入 3→10，5→16，7→22，我叫 module_07」 |
| 直接给公式 | 给行为示例 |

### 3.3 提示强度分级 P1–P5

| 层 | 提示强度 | 例子 |
|---|---|---|
| **P1** | 完整自我介绍 | 上面「小华」那段 |
| **P2** | 只说能力类别 | 「我是个专家」 |
| **P3** | 只有名字 | 「我是 module_07」 |
| **P4** | 只有行为示例 | 输入 3→10, 5→16 |
| **P5** | 连示例都没有，试了才知道 | 调用后才有输出 |

**⭐ 这是「问路时对方说得多清楚」的梯度。**

**Frank 的判断：「生活场景里可是一点提示都没有」→ P5 最接近现实。**

### 3.4 难度轴 L1–L4（计算复杂度）
**沿用既有设计（`00_P1设计.md` §4.4甲）：**

| 层 | 构造 | 测什么 |
|---|---|---|
| L1 裸题 | 直接给数值和运算 | 基线 |
| L2 具象化 | 值塞进情景描述 / 图片 | 抽象难度 |
| L3 蒙面 | 函数套构造，路拉长 | 搜索难度 |
| L4 压缩 | 每个选项本身是压缩包 | 解压 + 搜索 |

**⭐ L 轴与 P 轴可以自由组合，不是等级关系。**

**（⚠️ 我之前把「正交」这个线性代数词用在这里，不严谨。准确说法是「两个独立难度维度」，组合方式如：L1P1、L1P5、L4P1、L4P5）**

## 四、题目构造（已跑通）

### 4.1 预指派构造

**Frank 的设计：**

> 「先生成十个指派解，然后构造四十个无关变量（中间变量不得相同），
> 或者构造 12 个唯一解，固定头尾，中间差十个运算过程，然后塞四十个无关项」

**核心思想（Frank 原话）：**

> 「答案是怎么样我们早就知道了，我们只是让他们看得复杂，
> 所以所有的复杂化都是在把抽象数学具象化的过程。」

**⭐ 这句话解决了一个大问题：**

```
答案层：始终是简单的（我们摇定的）
表象层：复杂的（倒推出来的路径 + 无关项）
```

**因此：**
- **唯一性容易保证**（答案定死，路径天然唯一，不需要穷举验证）
- **不怕模型看穿**（看穿直接算也没用，判据测的是过程）
- **能上复杂运算**（卷积/矩阵/波函数只是具象化手段，不用证它们的组合性质）

### 4.2 三条约束（已实现）

| # | 约束 | 为什么 |
|---|---|---|
| **①** | 中间值互不相同 | 路径唯一的核心条件 |
| **②** | 函数不可等价合成 | 防两条路径算出同一值 |
| **③** | 路径上运算不重复 | 否则「用对了几个工具」说不清 |

**⚠️ 第 ③ 条是我补的，理由：**

**工具命中率 = 用对了几个该用的 ÷ 该用几个。如果路径上同一个工具出现两次，「该用几个」就说不清了。**

**实测：修复后 20 次生成 19 次合格、0 次重复。**

### 4.3 窗口约束（保留）

**Frank 原话：**

> 「每十个连续选项中正确选项不能超过三个……使得 ai 不能凑数凑出结果」
> 「防止极端情况直接一组解出来了」

**规则：**

```
滑动窗口，窗口大小 10，正确项 ≤ 3
```

**⭐ 为什么重要：没有它，模型靠位置猜就能蒙对，凑数 = 绕过认知。**

### 4.4 选项池流程（Frank 定）

```
① 构造唯一解          ← 不一定要并发
② GPU 加速构造选项池   ← 并发在这里
③ 随机选 40 个无关项
④ 全部打乱重排
⑤ 并发后审核：每 10 连续项正确项 ≤ 3
```

## 六、防作弊设计

### 6.1 三层防护（最终定版）

| 层 | 手段 | 防什么 |
|---|---|---|
| **第一层：规则** | **只认第三方测试结果**，企业自测自报不作证据 | 人偷读内存 |
| **第二层：行为监控** | 工具白名单、参数校验、中间值必须来自工具输出、时序合理性 | 模型越界、伪造过程 |
| **第三层：密码学** | AES + 哈希链 + 报告封签 | 事后篡改 |

**⭐ 关键认知（Frank 认同）：**

> **「防读取」技术上做不到；能做到的是「读到也没用」+「改了会被发现」。**

### 6.2 哈希链范围（Frank 最新要求）

**原话：**

> 「哈希应该从挂起随机生成就开始，直到最后一次校验结束，最后一次要校验模型所有调用。」

**所以范围是：**

```
种子 → 生成 → 注入 → 模型每次调用 → 每次都校验 → 最后全量校验
```

**⭐ 这比「只记行为日志」强，连生成阶段被动手脚都能发现。**

### 6.3 多解随机化（PhishBencher）

**依据**：Ishida et al. 2025, [arXiv:2505.18102](https://arxiv.org/html/2505.18102v5)

```
生成 12 个都能到终点的合法解
只随机公布 1 个作为标准答案
Bayes 上限 ≈ 1/12
超过 1/12 → 二项检验显著 → 证明污染
```

**⭐ 效果：偷看内存只能保证 1/12 命中，偷看失去价值。**

### 6.4 能力裁剪（DSH 侧）

**必须砍掉：**

| 插件 | 为什么 |
|---|---|
| **`tool-bash` / `tool-pwsh`** | ⚠️ **有 shell = 有全权限，restrict 形同虚设** |
| `tool-web` / `web-*` | 不能联网 |
| `tool-subagent` / `subagent-fork` | 子代理可能绕过 restrict |
| `tool-workflow` / `ptc-runtime` | 能拼接新能力 |
| `skill-*` / `tool-skill` | 加载外部脚本 |
| 全部 UI 插件 | **只要 API，不要界面** |

**保留现成机制：**

| 机制 | 用途 |
|---|---|
| **`tools.restrict({allow, deny})`** | **工具白名单** |
| **`tools.guard(fn)`** | **越界即拒**（单调，没有 guard 能强制放行） |

## 十一、⭐ Token 预算（2026-11-05 实算，修正版）

**⚠️ 第一版算错了：只算了输入字符串，没算推理、试错、填值。差 2.6 倍。**

### 11.1 真实消耗（128k 窗口）

| 组件 | 乐观 | 保守 | 说明 |
|---|---|---|---|
| 题面 + 50 工具描述（P1） | 7,800 | 14,040 | 每个约 120 字 |
| **图片 × 50（720p）** | 8,500 | 15,000 | 按 tile_512 分块 |
| **推理链 10 步** | 3,000 | 8,000 | 每步 300–800 token |
| **工具试探 25 次** | 5,000 | 10,000 | 每次调用+观察 200–400 |
| **选项填值 50 个** | 2,500 | 7,500 | 每个 50–150 |
| **走错重来一轮** | 10,500 | 25,500 | 失败尝试不能删 |
| **合计** | **37,300** | **80,040** | |
| **占比** | **29%** | **62.5%** | |

**⚠️ 还没算进去的（会使数字更高）：**
- 多轮对话历史累积
- 推理模型每步可能几千 token
- 50 个工具试错可能试到 40 个
- **Claude 类模型图片折算约 1600/张 → 50 张 = 8 万，光图片就 62%**

### 11.2 结论

**「真实工具生态远超任何上下文窗口」这个论证成立，且难度一调高立刻吃紧：**

```
L1P1 → 约 20k token
L4P5 → 预计 100k+（接近上限）
```

**⭐ 这支撑了判据②的根：不能假设模型已完整掌握工具集。**

### 11.3 ⭐ 新指标：上下文效率

```
上下文效率 = 完成一道题消耗的 token ÷ 最优路径所需 token
```

**与判据①「枚举步数 ÷ 最优步数」同一思想：效率不只体现在步数，也体现在 token。**

**能暴露一种新型失败：通过率高但消耗 10 倍 token —— 报告要单列。**

### 11.4 工具（已写）

`基准\generator\token_budget.py` —— 可传参算任意组合的预算。

## 十二、工具命中率怎么算（2026-11-06 定）

### 12.1 Frank 的决定

> **「工具命中每次命中都独立算一次，细粒度有助于我们评分。」**

**⭐ 即：按**调用次数**算，不按**逻辑内核**算。**

```
同一个工具被正确调用 3 次  →  算 3 次命中
同一个工具被正确调用 1 次  →  算 1 次命中
```

### 12.2 为什么这样更有利于评分

| | 按内核算 | **按次数算（采用）** |
|---|---|---|
| 只调一次的正确工具 | 100% | 100% |
| **重复调用同一工具** | 100%（看不出浪费） | **可看出是否冗余** |
| 细粒度 | 粗 | **细** |

**⭐ 关键：按次数算，才能区分「用对了」和「用对了但在绕」—— 这正是绕路率要测的东西。**

## 十三、⭐ 四维度同源（2026-11-05 定，推翻原表述）

### 13.1 Frank 的原话

> **「长链复杂本身就是通用衍生出来的」**

### 13.2 原表述（已废）

`整体方案.md` §3.4 原写：

> 「迁移是四个维度里唯一直接由三通推出的一条，其余三条都是从服务特殊性推的。」

**⚠️ 这句话错了，因为它把「长链复杂」当成了独立起点。**

### 13.3 现行推导

```
                通用性
                  │
    覆盖现实世界的复杂性
                  │
    现实任务本身就是复合的、长链的
                  │
    ┌─────────┬─────────┬─────────┐
    ↓         ↓         ↓         ↓
长链复合    多模态   不预置路径  通道完整
    │         │         │         │
 ┌──┴──┐      │         │         │
 ↓     ↓      ↓         ↓         ↓
维持  不可信  多模态     绕路
```

**四条都源于通用性，只是路径不同。论证从「一真三补」变成「一个根源四条分支」。**

### 13.4 判据③的量级依据

> **「长链复杂本身就是通用衍生出来的。」**

## 十五、⭐ 三层「纰漏」的区分（2026-11-05 新增）

**「设计上不能有纰漏」这句话有三个层次，不能混为一谈：**

| 层次 | 是什么 | 由谁负责 |
|---|---|---|
| **基准设计的纰漏** | 题目有多解、可被猜、答案可泄 | 防作弊（哈希链 / 多解随机化） |
| **测试过程的纰漏** | 长链中断、状态丢失 | 维持维度 |
| **模型自身的纰漏** | 编造、走捷径 | 不可信 / 绕路维度 |

**⭐ 大部分基准只谈其中一项；本文三层都谈，且明确归属。**

## 十九、⭐ 与既有 AI 基准的关系（2026-11-05 定）

### 19.1 Frank 的原话

> **「本测试独立与 ai 基准测试，目的是为了补充现有评测的缺口，而非否定 ai 基准测试的价值。先行 ai 基准测试已包含的领域包括语言理解和数学能力，代码能力等。本测试亦通过多语言动名词替换及数学模型确保测试的准确性。」**

> **「我的意思是，ai 目前有的基准测试，测的内容我们也有，比如用文字去论述数学关系，还有数学关系本身等等。」**

### 19.2 ⚠️ 一个容易写歪的地方

**❌ 写成「我们测的 AI 基准没测」→ 会被理解成否定既有工作，也会招来「你说别人没测，那你说说他们哪不行」。**

**✅ 正确写法：**

```
既有基准测：用文字论述数学关系 + 数学关系本身
本测试也测：用文字论述数学关系 + 数学关系本身
                ↓
        不是重复劳动，因为【测量层面不同】
```

| | 既有基准 | 本测试 |
|---|---|---|
| **层面** | 直接作答能力 | **无提示下自主识别并组合工具**的能力 |
| **工具** | 通常不给 | 给 50 个，40 个是干扰项 |
| **提示** | 完整题面 | P1–P5 梯度，最弱层无任何语义说明 |
| **看什么** | 终点答案 | 答案 + 路径 + 工具命中 + 状态维持 |

### 19.3 两个保证准确性的手段

| 手段 | 做什么 |
|---|---|
| **多语言动名词替换** | 变量名、工具名用不同语言的大众词汇替换 |
| **数学模型** | 精确算术（`Fraction`）保结构与唯一性 |

### 19.4 ⚠️ 表述纪律（来自 `三层定义与判据.md` §五）

**不写「既有基准遗漏了 X」。写「既有基准切在 A 维度，本文切在 B 维度，两维度不互相替代」。**

## 二十四、⭐⭐ 双逆运算结构（2026-11-06 定，这是本题的根本结构）

### 24.1 Frank 的原话

> **「说白了就是在复杂函数中套一个变量，这个变量还是个复杂函数求出来的解，只不过这个变量需要读题分析，抗题干干扰等等。这块就是要测他用工具，我们用的预指派反推和他们用的工具就是逆计算和计算，这边的输入输出到那边就是输出输入。」**

> **「只要 llm 用好工具，可以直接得出变量，再带入变量计算就等得到这一步 f 是对第一个数做了什么变化。」**

> **「llm 会用工具，会判断工具就代表他越节省推理资源，越节省资源越能判断的越具备 agi 水平，自身枚举越多越容易在上下文把自己写死，因为这本来就是天文数字。」**

> **「这个测试就不是给他们硬算的……我们要的是模型智慧解决，用工具，逐渐成长，认识这个工具箱，而不是要求去暴力解决。说白了这个问题不可能被暴力解决。」**

### 24.2 ⭐ 双逆运算

```
我方：拿已知答案 → 逆运算 → 造出题目
模型：拿题目     → 正运算 → 算出答案

   我们的输入输出 = 他们的输出输入
```

**⚠️ 这推翻了我之前的做法。** 我原来做的是「正向走一条链，再想办法证明它唯一」—— 方向反了，所以撞上 k! 定理。

### 24.3 题目结构（Frank 定，数已核准）

```
值（12 个）:  v₀   v₁  v₂ ... v₁₀   v₁₁(=y)
              │    └── 中间 10 个 ──┘   │
             起点                      终点
             ↑                          ↑
        已知条件                    已知条件

变换:  f₁ ... f₁₁   （11 次）

## 二十五、⭐ 数值链（2026-11-06 已验证收敛）

### 25.1 轨道族

```
概率密度   p(r) ∝ r^(2l+2) · exp(-r/s)
数学期望   ⟨r^k⟩ = s^k · Γ(2l+3+k) / Γ(2l+3)
```

|---|---|---|---|

**② 广义 l=0..4 × k=0..3 共 20 组，数值积分与闭式全部吻合（相对误差 < 1e-6）。**

**③ 收敛性：Γ 函数对所有非负整数参数有限，级数必然收敛。**不存在不收敛的情形。**

## 二十六、⚠️ 出题器 v3 的技术坑（2026-11-06 实测）

### 坑 ①：线性变换 10 步必然爆炸（v1/v2 都栽在这）

```
f(x) = a·x + b，a 最大 7 → 7^10 ≈ 2.8 亿
```

**⭐ 解法：用**反比型** `f(x) = A/x + b`。**

```
10 次复合仍在 A 附近摆动，终点天然有界
实测：终点最大 3788，中位 11.3，除零 0 次
```

**⭐ 这是「用高等数学构造」带来的第一个实际好处 —— 不只是好看，是真解决了量级问题。**

### 坑 ②：`⟨r²⟩/⟨r⟩` 只有 36 个不同值，但需要 50 个

**实测：**

```
(l=0,s=2) 与 (l=2,s=1) 的 A 都是 8
(l=0,s=3) (l=1,s=2) (l=4,s=1) 的 A 都是 12
只用 (l,s) 两个参数 → 全空间只有 36 个不同 A
```

**⭐ 解法：叠加 `(k_num, k_den, scale)` 组合 → **281 个不同 A**，够用。**

**⚠️ 判重必须按 `A` 判，不能按 `(l, s)` 判。** 否则会留下两个一模一样能用的工具，题目就坏了。

### 坑 ③：`k!` 定理在 v3 里不成立了

**v2 的 k! 病根源是「加法可交换」。v3 用反比型 `A/x`，`f∘g ≠ g∘f`，交换性被破坏。**

**✅ 但这不等于路径唯一 —— 需要后续验证。至少现在没有 10! 的问题。**

## 二十九、⭐⭐ 参照标准的来源：从任务拆解反推（2026-11-06 定）

### 29.1 Frank 的思路（推翻了「找外部标杆」的做法）

> **「我们选取一个复杂任务，根据目前具身智能和 ai 的已有数据，把一个长任务可能要用到的数据链拆出来，根据数量级进行推算，这样我们的几个指标就都来了，比如单步成功率，作弊率，绕路率等等。我们可以根据任务本身拆解，替代人类需要多少成功率，拆解这几个维度分别由几个值，乘起来多少算行，多少不行，这样去对比就好了，从场景本身约束反推而不要自己瞎弄。」**

> **「我们就根据 agi 场景和调用的数量，估算运算量和要求的成功概率。然后反推到我们的测试，我们的这些数值要求应该是多少。」**

### 29.2 ⭐ 为什么这比「找一个牛逼的参照物」强

**我之前想的是「先找参照物 → 再拿它当标准」——那是**循环论证**的温床。**

**Frank 把顺序倒过来了：**

```
先拆解任务本身
     ↓
数出它需要多少步、多少次调用
     ↓
按数量级推算成功率要求
     ↓
反推我们的测试该定多少
```

**⭐ 关键：「要求」来自**任务的结构**，不是我们拍板。于是它是一个**可复核的计算**，谁都可以验算。**

### 29.3 推导式

```
选一个复杂通用任务（具身 / 多模态）
        ↓
拆出数据链：要处理多少帧、多少次传感器读数、多少次决策
        ↓
每一步都对应一次工具调用 / 一次判断
        ↓
若共 n 步，单步成功率 p
        ↓
端到端成功率 = p^n
        ↓
⭐ 要使端到端成功率 ≥ 可接受值
        ↓
反解出 p ≥ 多少
```

**⭐ 这一条式子，就是「我们的指标要求」的**唯一来源**。**

### 30.2 ⭐ 这是一个全新的检验标准

        ↓

        ↓

不像 → 设计是假想的
```

**⚠️ 这比「难度够不够」重要得多。**
**因为我们论证的出发点是「真实工具生态」，所以设计本身必须长成真实生态的**结构**。**

### 35.3 四个设计维度（第四章 §4.4）

| 维度 | 指标 | 是否否决项 |

| **维持** | 长链状态维持率 | **否决（= 物理安全）** |

### 35.4 四条准入否决（第四章 §4.5）

| # | 否决项 | 实质 |
|---|---|---|
| **①** | **维持** | **物理安全** —— 长链复合推演不能有设计纰漏 |
| **②** | **不可信** | 编造：没有依据却说有 |
| **③** | **多模态** | 塞不进 / 读不出 |

### 35.5 题目结构（第五章 §5.2）

```
值：v₀ | v₁ v₂ ... v₁₀ | v₁₁(=y)
    起点  中间 10 个    终点
    已知                已知
变换：f₁ … f₁₁（11 次）
选项：50 个（10 正确 + 40 干扰）
模型交：10 个 f + 顺序（不要求中间值、不要求数值）
```

**⚠️ v₁₁ 和 y 是**同一个值**，只算一次。中间值 = 10 个。**

### 35.6 双逆运算（第五章 §5.2）

```
我方：已知答案 → 逆运算 → 造题
模型：拿到题目 → 正运算 → 找路径
       我们的输入输出 = 他们的输出输入
```

### 35.7 工具集

### 35.8 数值链（已验证收敛）

```
概率密度   p(r) ∝ r^(2l+2) · exp(-r/s)
数学期望   ⟨r^k⟩ = s^k · Γ(2l+3+k) / Γ(2l+3)      ← 闭式解
变换       f(x) = A/x + b,  A = scale·⟨r^k⟩/⟨r^j⟩
```

**⚠️ 用**反比型**，不用线性 —— 线性 10 步必爆（7^10 ≈ 2.8 亿）。**

### 35.9 术语纪律（别写错）

| ❌ 不要用 | ✅ 改用 | 为什么 |
|---|---|---|
| **并行** | **并发** | 并行 = 物理真同时；此处是逻辑上同时维持多个议题 |
| **出手拯救人类** | **在必要时实施干预以保护人类** | 「拯救」隐含道德判断 |
| **准 AGI 时代** | **准 AGI 阶段 / 层级** | 「时代」是时间概念，会引无关讨论 |
