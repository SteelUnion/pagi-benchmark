## 〇、为什么重构

**2026-11-08 弗兰克判原设计系统性错误：**

> 「只是llm解题变成全枚举了，因为每一个步骤的值都跟上一个步骤相关了，

>  你根本不知道最终的值是多少，这个思路大错特错。」

**病根定位：**

```
原设计：10 个链节【嵌套复合】→ 11 个节点 → 终值 = 11 个节点的连乘

   ⋮
试到第 10 步 → 才知道终值对不对
    ⚠️ 中途零检查点 → 只能穷举 → 考的不是判断力，是枚举耐力
```

## 一、链节（单链节）的定义

### 1.1 口述原文

> 「单个链节包括最上面的yn值也就是因变量，我们要利用反函数两次复合反向求出xn来，
>  每一组y和x是一一对应的，xn被称为自变量。
>  yn用反函数求出xn的过程，目前算法已有，可以参考。
>  而xn求yn配正函数则成为选项。
>  这样的一个部分是链节。」

### 1.2 拆解成条款

| # | 条款 | 含义 |
|---|---|---|
| L1 | 链节含一个 **yₙ** | yₙ 在链节的最上面，**它是因变量** |
| L2 | 链节含一个 **xₙ** | xₙ **被称为自变量** |
| L3 | **每一组 y 和 x 一一对应** | 给定 yₙ 唯一确定 xₙ；给定 xₙ 唯一确定 yₙ |
| L4 | **yₙ → xₙ 走反函数，两次复合反向求** | `xₙ = f⁻¹( yₙ / cn / c )` —— 除两次 |
| L5 | **xₙ → yₙ 配正函数，成为选项** | `yₙ = f(xₙ) · c · cn` —— 乘两次 |
| L6 | 这一整套就是**一个链节** | 一个链节 = 一个 (xₙ, yₙ, f, c, cn) 五元组 |

### 1.3 「两次复合」「两次反向」的准确含义

**⚠️ 这是最容易做错的地方，写死在这里：**

```
正向（乘两次）：  yₙ = f(xₙ) · c · cn
反向（除两次）：  xₙ = f⁻¹( yₙ / cn / c )

⭐ 为什么是「两次」：
   c  和  cn  是两个独立的乘数，
   正向各乘一次 → 反向各除一次。
   ⚠️ 顺序必须严格互逆：先乘 c 后乘 cn，就先除 cn 后除 c。
   （数值上乘法可交换，但符号上不可交换 —— 写题面要严格对上）
```

### 1.4 一一对应（单射 + 满射）

**⚠️ 这是链节成立的前提，不是装饰：**

- f 必须在 xₙ 的取值范围上**严格单调**（可逆）
- f⁻¹ 必须落在 f 的定义域内
- yₙ 必须在 f 的值域内 ⇒ 否则 xₙ 无解，链节作废

**这就是「唯一解」的来源：一个 yₙ 只对应一个 xₙ。**

### 1.5 ⭐ 嵌套结构：链节内嵌套 + 外部连乘（2026-11-08 弗兰克定）

> 「我们现在算法变了，不是暴力叠加嵌套了，而是**链节内嵌套加外部连乘**，
>  误差出现的来源不同了。」

**⚠️ 我上一版 §1.3 把「两次」理解成 `c` 与 `cn` 两次乘，把嵌套层理解成 1 层。判错。
弗兰克这句「链节内嵌套」= 有效。**

```
┌─────────────────────────────────────────────────────────┐
│ 链节 L001                          ← 链节【内嵌套】        │
│                                                         │
│             g₁        g₂        g₃                      │
│   X001 ────▶ · ────▶ · ────▶ · ＝ Y001                  │
│   (自变量)                    (因变量)                   │
│                                                         │
│   每节嵌套 3 层（g₁/g₂/g₃ 各自是一个数理包，各带 c/cn）    │
└─────────────────────────────────────────────────────────┘

   ⚠️ 三种东西都不一样，别混：
      层次   g₁ … gₘ        链节【内】的嵌套层
      链节   L001 … L010     连乘的每一项
      链条   Y001 × … × Y010 链节【外】的连乘
```

**⭐ 误差的三个来源（弗兰克说「来源不同了」）—— 一个都不能漏：**

| 来源 | 位置 | 每个链节几次 |
|---|---|---|
| ① 层内两次乘 / 两次除 | 每层 `f·c·cn` / `f⁻¹(y/cn/c)` | **m 次**（m 层） |
| ② 层间串联传播 | 上一层输出当下层输入 | m−1 次 |
| ③ 链节连乘 | `A000 × Y₁ × … × Y₁₀ = Z` | 10 次 |

**⚠️ 原设计只有 ③ 被考虑过（嵌套复合），① 和 ② 是这次新增的。**

### 1.6 ⭐ 60 个 y 的构造（2026-11-08 弗兰克定）

> 「现在链条和 x 都有了，只需要把**运算出 x 的反函数，其成对的那个函数找出来**，
>  把 **x 作为自变量代入两个嵌套函数**计算，那么就能得到 y。对吧，
>  以我们的方案为例，构造了 60 个 y，其中 10 个真 y，50 个假 y，
>  但**每个 y 都有对应的随机函数和 x 值**，
>  这样就构造出了 10 个正确选项和 50 个干扰选项。」

```
60 个 y
├── 10 个真 y   ← 链条上的 Y001…Y010
└── 50 个假 y   ← 干扰项

⚠️ 关键：不区分真假，60 个走【同一条构造流水线】

    每个 y 都配：  自己的随机函数（嵌套 m 层）
                   自己的 x 值
                   自己的 c / cn

    真 y ：  由链条连乘约束决定（A000 × ∏Y = Z），x 反推得到
    假 y ：  同样走一遍 → 也是合法链节 → 和真 y 【长得一样】
```

**⭐ 为什么这样干扰项看不出破绽（老代码已经验证过这个原则）：**

> `vectorform.py` 原话：正确答案与干扰项「本身是一个循环里的邻居」。

**⚠️ 老算法是「先随机造 w，再参照 y→x 的定义域修正」，
新算法是「每个 y 都配一套完整的随机函数 + x」—— 干扰项从源头就是同构的。**

### 1.7 ⭐ 唯一性的判据：选出恰好能算出 Z 的那 10 个（2026-11-08 弗兰克定）

> 「对，**模型必须选出 10 个 y 值，恰好能把 z 算出来**，
>  其他的构造项都避开了 10 个 yn，且不能等于任何中间体，
>  这强制使得他们不能参与 z 的构造，
>  **从原理上就不是正确答案**。」

**⚠️ 2026-11-08 实测（老代码，seed=20261107，一条链）：**

```
节点 11 个（A000 + 10 个 Y），Z = -2.492587963774815e-06

按子集大小穷举全部组合，看哪个乘积 == Z：
   取 1..10 个：全部 0 种命中
   取 11 个  ：1 种命中   ←  就是唯一的那个全集
```

**⇒ 老算法里正确答案取的是【全部 11 个】，不是 10 个。核 11 是从 11 个值里挑 11 个。**
**⇒ 新设计的 10 个必须说清楚是「10 个 Y」，A000 是链条给出的链头，不计入选择。**

**⭐ 唯一性的双重保障：**

| 保障 | 判据 | 效果 |
|---|---|---|
| ① 连乘值被锁死 | `∏Y = Z / A000` | 连乘值只有一个可能 |
| ② 干扰项避开三个集合 | 避开 ①Yₙ 本身 ②Yₙ 连乘中间体 ③Z/A000 | 任何干扰项替换掉某个 Yₙ，连乘必然跳出 |

**⚠️ ② 的"避开"是实质性的：不是"挑一挑不撞"，而是**
**干扰项在数学上【不可能】参与构造 —— 这是原理上的排除，不是统计上的。**

**⚠️ 待定：`A000` 本身要不要也在"避开"的集合里？**
**（干扰项恰好等于 A000 时，它能不能顶替 A000 参与连乘？这不是"参与 Z 的构造"，而是"顶替链头"。**
**弗兰克说的"避开 10 个 yn 和中间体"没提这个，需要确认。）**

### 1.8 ⭐ 定案：A000 和 Z 一样排除（2026-11-08 弗兰克）

> 「你自己刚刚写了，构造的值不可以等于 a 和 z 啊，那不就排除了吗，
>  **所有跟 z 相关的值都排除了**」

**⚠️ 弗兰克说得对 —— 我上一版 §1.6 自己写了「链条连乘约束」，A000 和 Z 都在里面，
    却在 §1.7 又去问「要不要排除 A000」。这是自相矛盾。已定：排除。**

**⭐ 排除集合 = 「跟 Z 相关的全部 13 个值」：**

```
设   A = A000（链头）      Z = 链尾值         P = Z / A  （被锁死的连乘值）

排除集合 S（干扰项 w 不得等于其中任何一个）：
  ┌─────────────────────────────────────────────┐
  │  ① A000                    A        1 个     │
  │  ② Y001 … Y010             10 个             │
  │  ③ 连乘中间体               9 个             │
  │       A·Y₁, A·Y₁Y₂, …, A·Y₁…Y₉               │
  │  ④ Z                        Z        1 个     │
  └─────────────────────────────────────────────┘
                        合计 21 个
```

**⚠️ 中间体是 9 个不是 10 个 —— 因为 `A·Y₁…Y₁₀` 就是 Z 本身，已算在 ④ 里，不能重复计。**

**⭐ 为什么这 21 个都排除 ⇒ 原理上排除：**

```
要凑出 Z，任何一组数相乘必须恰好 = Z = A × Y₁ × Y₂ × … × Y₁₀

既然 w 不等于这 21 个中的任何一个：
    · w 不能顶替 A          （w ≠ A）
    · w 不能顶替某个 Yₙ     （w ≠ Yₙ）
    · w 不能顶替某个中间体  （w ≠ 中间体）
    · w 不能直接顶替 Z      （w ≠ Z，否则连乘只剩 w 一项，与其他项矛盾）

⇒ 无论 w 出现在连乘的哪个位置，等式都不成立
⇒ w 在数学上【不可能】参与 Z 的构造
```

**⚠️ 这个排除是【原理上的】，不是统计上的。这就是唯一性的根。**

**⚠️ 提醒：老代码 `make_decoys_gpu` 只避开了「11 个节点」，
    没有单独避开中间体和 Z 本身（因为那时 Z 是连乘结果，不在节点里）。
    新设计必须把 21 个全给进去 —— 这是重构要补的。**

### 1.10 ⭐ 值域 / 定义域的限制：两层系数 c 与 cn（2026-11-08 弗兰克）

> 「好了，接下来是**对值域和定义域的限制**，最先的是几个系数 **c 和 cn** 什么的，
>  这些东西**能调正负，能放大缩小**，可以让随机到的 y 值可以被反函数处理得到 x，
>  相应的，**在构造选项的时候，为了得到那个 y，也要把系数抵消掉才行**。

**⭐ 老代码里的两个案例（已核）：**

### 1.10b ⚠️ 必须分清：一个链节里有「两组」系数

**⚠️ 这是新设计才出现的层次，老代码没有，别照抄混用：**

```
链节 L001（内嵌套 m 层）
  ┌──────────────────────────────────────────────────┐
  │  层 1:  g₁  · c₁ · cn₁                            │
  │  层 2:  g₂  · c₂ · cn₂                            │
  │   ⋮                                              │
  │  层 m:  gₘ  · cₘ · cnₘ                            │
  └──────────────────────────────────────────────────┘
                    ↓ 得到 Y001
  外层:  A000 × Y001 × … × Y010 = Z        ← 这一层【没有】系数
```

**⚠️ 只有链节【内】有 c/cn，链节【外】的连乘是纯乘法，不加系数。**
**否则 `∏Y` 的定义会被污染，2047 组合的判据失效。**

### 1.10c ⭐ 构造选项时「把系数抵消掉」

**弗兰克：「在构造选项的时候，为了得到那个 y，也要把系数抵消掉才行。」**

**⇒ 这是同一个恒等式的两面：**

```
造题（y → x）：   x = f⁻¹( y / cn / c )          ← 除两次，把系数从 y 身上剥掉
出选项（x → y）： y = f(x) · c · cn              ← 乘两次，把系数原样加回去

⚠️ 用的必须是【同一组】c 和 cn —— 不是重新生成的一组。
   包里 c 定死（打包时），cn 存在系数表里按层取（老代码 undo() 就是这么做的）。
```

**⚠️ 这就是「一一对应」能成立的实际原因：**
**系数在往返中必须精确抵消，否则 y 回不来，链节就作废。**

**⚠️ 实测支撑：36 组（12 包 × 3 种 cn）最坏往返误差 5.33e-16 —— 抵消是干净的。**

### 1.10d 值域 / 定义域怎么被系数解开

**弗兰克：「可以让随机到的 y 值可以被反函数处理得到 x。」**

```
问题：  随机抽到的 y 可能不在 f⁻¹ 的定义域里 → 反推不出来
解法：  调 cn（和调 c 的方式不同，c 是打包时定死的，不能动）

  cn 能做两件事：
    ① 缩放   ±10^k     把 y 拉进 f⁻¹ 的定义域
    ② 翻号   ±1        负 y 撞只收正的反函数时，乘 −1 就接上（anchor.py 的实测：
                       betaln/logit/erf/log2/ndtri 五条断了，cn=−1 全接上）

⚠️ 为什么只取 10 的整数次幂（choose_cn 原话记着）：
    ① 题面干净（×10、×0.01）
    ② 十进制精确表示，不引入额外舍入
    ③ 可复现（不需要存浮点数的二进制）
```

**⚠️ 老代码 `choose_cn_each` 只搜正幂次 `10.0 ** k`，k∈[−30,30]，
    **没有负号**。带符号是 `anchor.fit_cn_to_next` 才有的。新代码要两者合一 —— `link.repick_cn` 已经这么做了。**

### 1.11 ⭐ m 层可以被「放缩」构造消掉（2026-11-08 弗兰克）

> 「**m 层应该可以通过构造来消除吧**，无非就是对推出来的值做一个放缩处理而已。
>  confirm，**你正向运算的时候能放缩两次，逆向回来就能放缩两次**。你想想」

**⭐⭐ 想通了：m 层不需要当成「m 层」来管 —— 每层的放缩都是同一个操作，串起来还是同一个操作。**

```
第 1 层：  v₁ = g₁(v₀) · c₁ · cn₁          ← 放缩一次
第 2 层：  v₂ = g₂(v₁) · c₂ · cn₂          ← 放缩一次
   ⋮
第 m 层：  vₘ = gₘ(vₘ₋₁) · cₘ · cnₘ        ← 放缩一次
                                    ↓
                          Y = vₘ

反向（严格倒序，每层除两次）：
          x = g₁⁻¹( g₂⁻¹( … gₘ⁻¹(Y / cnₘ / cₘ) … / cn₂ / c₂) / cn₁ / c₁ )
```

**⭐ 每层都是「两次放缩 / 两次反向放缩」，m 层就是重复 m 次同一件事。
不需要为 m 层单独设计任何东西 —— 这就是弗兰克说的「通过构造来消除」。**

**⭐ 实测（2026-11-08，随机 200 条 m∈{2,3,4} 嵌套链，池子 74 个包）：**

```
成功 131 条，反向断 52 条，cn 挑不出 17 条
成功率 65.5%     最坏往返误差 1.32e-10（门限 1e-9，过）

样例：
  m=3  expn*10 + ive*0.1 + acos*1          x0=4.025    xb=4.025    2.74e-14
  m=4  i1*1e-08 + asin*1 + ive*1 + gammaln*1  x0=19.0005 xb=19.0005 1.87e-16
  m=2  exp*0.1 + acos*1                    x0=0.4595   xb=0.4595   1.09e-15
```

**⚠️ 但 65.5% 的成功率说明：m 层不能「随便挑 m 个包就成」—— 必须逐层验。**

**⚠️ 52+17=69 条失败的具体原因是（这就是重构必须处理的）：**

| 失败类型 | 条数 | 原因 | 对策 |
|---|---|---|---|
| 反向断 | 52 | 某层输出把下一层推到了 f⁻¹ 的值域外 | 逐层定 cn 时就要判「下一层接得住」 |
| cn 挑不出 | 17 | 该层输出量级一个 `10^k` 压不进去 | 换锚点侧别，或换包 |

**⇒ 这和老代码 `layerchain` 的结论一致：正向时就要验「本层×cn 能不能被下一层接住」，
    不能等反向了才发现断。**

## 三、x 与 y 的具体编码

### 3.0 ⭐ 2026-11-08 弗兰克修正：y 才是最初的数

> 「现在定义完以后你知道，**y 才是最开始的数**，x 是逆推的，用反函数算的，
>  那么大模型做题的时候，我们可以生成我们需要的这样的链节，想要多少生成多少。」

**⚠️ 这句话纠正了 §1.2 的一个隐含理解，写死在这里：**

```
错的读法：  x 是输入，y 是输出          ← 数学上算的时候是这么算
对的读法：  y 是【最初的数】，x 是【逆推出来的】   ← 出题时是这么造

⭐ 造题顺序：  先有 y  →  反向除两次 f⁻¹  →  得到 x
⭐ 解题顺序：  拿到 y  →  反向除两次 f⁻¹  →  得到 x     （同一件事）
⭐ 选项来源：  x  →  正向乘两次 f  →  得到 y           （配正函数）
```

**⭐ 关键推论：链节可以【想要多少生成多少】—— 因为每节都是独立造的，互不依赖。**
**这是这次重构的全部意义：不嵌套 ⇒ 不枚举。**

### 3.0b 实测先摆在这里（看过代码后量的）

**⚠️ 两次乘 / 两次除会不会丢精度？实测 12 个包 × 3 个 cn，共 36 组：**

```
最坏相对误差 = 5.33e-16     门限 1e-9   →  ✅ PASS
```

**⚠️ 所以「除两次」在数值上成立，链节可以做。**

**⚠️ 但实测同时暴露一个必须堵的坑：**

```
tanh / erf / asinh / asin 在 search 里取中点 → 中点正好是 0
y = 0   →   反向 f⁻¹(0) 回来还是 0   →   误差 0，看着「完美」
                                          ⚠️ 其实这个点毫无信息
```

**⇒ 定一条硬规矩：`x ≠ 0`，`y ≠ 0`。见 §3.3。**

### 3.1 编码表

**⭐ 2026-11-08 Frank：「看看能不能定义 x 和 y 的具体编码，其实就是在原来的基础上，
把 yn 之间互相嵌套复合的函数，给单拎出来，变成每个 yn 和 xn 复合。」**

**结论：能。而且不用新造一套前缀 —— 把原来的编码「降一维」就行。**

| 东西 | 新编码 | 例子 | 原来的编码 | 变化 |
|---|---|---|---|---|
| **链节** | `L###` | `L001`…`L010` | 没有这个概念 | **新增**，一节一个 |
| **因变量** | `Y###` | `Y001`…`Y010` | `X001`…`X010`（链节自变量） | 前缀 `X`→`Y`，**数值照抄** |
| **自变量** | `X###` | `X001`…`X010` | 没有（原来 X 指的是上面的东西） | **新增**，一节一个 |
| **函数** | `E###` / `H###` | `E001` / `H003` | `E###` / `H###` | **完全不变** |
| **系数 c** | `C###` | `C000` | `coef_code` | **完全不变**（打包时定死） |
| **系数 cn** | `C##` | `C01` | `C00`…`C09` | **完全不变** |
| **预指派** | `A000` | `A000` | `A000` | **不变**（但含义见 §3.2） |

**⭐ 下标对齐：`Y001` 与 `X001` 同属 `L001`。**
**一条链节就是 `(X001, Y001, f001, c001, cn001)` 这一个五元组。**

### 3.2 ⭐ 链条结构（2026-11-08 弗兰克定稿）

> 「然后是链条，**a000 是链头，后面是链身，结尾是链尾值，头尾数值作为已知条件给出**。
>  中间设计成**连乘 10 个 yn**，那么就变成乘法叠加了。
>  只需要让批量生成的**干扰项避开 yn 连乘的所有中间体以及 yn 本身的值**，
>  就不会生产出其他解了，这一步确保解是唯一的，
>  关于干扰项数量，链节 yn 数量啥的你参照老代码写就行。」

```
                        头尾都给（已知条件）
     ┌──────────────────────────────────────────────────────┐
     │                                                      │
   A000  ──×──  Y001 ──×── Y002 ──×── … ──×── Y010  ──＝──  Z
   （链头）      └──────────── 链身（10 个 yn）──────────┘   （链尾值）
     已知                         待求                        已知

   ⭐ 关系：A000 × Y001 × Y002 × … × Y010 = Z
   ⭐ 已知 A000 和 Z ⇒ 10 个 yn 的【连乘】被定死 ⇒ 解是唯一的一组
```

**⚠️ 注意各编号的含义彻底变了，别按老理解：**

| 编号 | 之前 | **现在** |
|---|---|---|
| `A000` | 预指派链头，链上第 0 个**节点** | **链头**，题面给的已知数（不是节点，不参与链节） |
| `Y001..Y010` | 不存在（那时叫 X，是链节**自变量**） | **链身**，10 个 yn，**每节一个，各自独立** |
| `X001..X010` | 链节自变量（= 上一节输出） | **每节的 x，由 y 反算出来**，不进题面 |
| `Z` | 叫 `final`，11 节点连乘 | **链尾值**，题面给的已知数 |

**⇒ `A000` 的归属确定了：保留，作为链头已知量（就是上一轮问的「乙」方案，但地位变了 —— 它和 Z 一样是【给的】，不是【算的】）。**

### 3.2b 唯一性怎么保证（弗兰克这条是关键）

**⚠️ 这不是「挑一挑不撞就行」，这是唯一性的**证明**：**

```
约束：     A000 × ∏ Yₙ  =  Z           （A000、Z 已知）
          ⇒  ∏ Yₙ = Z / A000     —— 连乘值被锁死，是一个确定常数 P

要证唯一： 不存在另一组 (Y₁′…Y₁₀′) 使得 ∏ Yₙ′ = P 且每个 Yₙ′ 都是选项里的合法值

做法：    干扰项 w 必须避开【两个集合】
           ① Yₙ 本身             （10 个值）
           ② Yₙ 连乘的所有中间体  （A000·Y₁, A000·Y₁Y₂, … ，共 10 个）
          ⇒ 任何 w 一旦替换掉某个 Yₙ，连乘必然跳出 P
          ⇒ 没有第二组解
```

**⚠️ 中间体一共 10 个（含终值），不是 11 个 —— `A000` 是起点，不在连乘路径内。**

### 一、最终定下来的数学

```
构造（y → x，用反函数）
    v = f1⁻¹( c1 · y )
    x = f2⁻¹( c2 · v )

正向（x → y，用原函数）
    y = f1( f2(x) / c2 ) / c1

c = ±1 × 10^k   一个数，同时管正负和数量级
```
