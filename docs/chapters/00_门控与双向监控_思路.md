## 〇、一句话

**从「事后查」升级成「事前拦」—— 模型改不了，而不是改了才被发现。**

---

## 一、为什么这件事重要（Frank 原话）

> **「我们不都把 dsh 接进来了吗，那大不了写个插件插上去在 dsh 盯住模型行为和日志就行了，
> 违规改动直接由插件拦截行为终止测试。」**

> **「就是说不允许模型写入日志，写入就激活，
> 我们本来就用的沙箱模式，可以把我们现在的权限门插件改改，
> 限定 llm 能调用的能力，把考试以外的能力直接拦截了，并且当场提醒，
> 就像你没有 confirm 不能持久化操作一样。」**

> **「然后这边我们的基准测试程序监控门控是否开启，双向监控，
> 一旦那边尝试关掉门控，这边考试直接拉闸。
> 那边模型想作弊改东西，门控把着权限，提醒模型用正确方式答题，否则被判舞弊。」**

## 二、三层防护的对比

| 层 | 手段 | 时机 | 效果 |
|---|---|---|---|
| **第一层** | 哈希链 + AES | **事后**验 | 能发现被改，但**已经改了** |
| **第二层** | DSH 日志哈希锚定 | **事后**验 | 同上 |
| **⭐ 第三层** | **门控拦截** | **事前**拦 | **改不了** |

**⭐ 三层都要，但第三层最有效。**

---

## 三、双向监控的结构

```
        基准测试程序（我们）              DSH 门控插件
              │                              │
         ① 监控门控是否开启 ────────→  ② 门控状态定时通报
              │                              │
         ←────────── 心跳 ──────────────────│
              │                              │
     ③ 任一侧挂了/超时 → 拉闸               │
              │                              ↓
              │                    ④ 模型要写日志 / 改文件
              │                              ↓
              │                    ⑤ 拦截 + 当场提醒
              │                              ↓
              └──────────────────  「用正确方式答题，否则判舞弊」
```

### 3.1 心跳机制（Frank 定）

> **「把 dsh 的接口向外定时通报权限+门控，心跳可以」**

| 项 | 设计 |
|---|---|
| **通报内容** | 当前权限档位 + 门控开关状态 |
| **通报方式** | 定时（间隔待定） |
| **判据** | 基准侧超时未收到心跳 → **拉闸** |
| **两侧都挂** | 任一方向断 → 停考 |

**⚠️ 为什么两侧都要心跳：**

```
只有单向：门控挂了基准侧不知道 → 考试在无门控下继续
只有单向：基准侧挂了门控不知道 → 门控自己继续，但没人判分
⭐ 双向心跳，两边都能发现对方没了
```

## 四、门控要拦哪些能力

### 4.1 ⭐ 已定（2026-11-06 Frank）

> **「我们通过系统提示词注入试卷，不让它读，它思考并在草稿纸作答，我们直接监控哈希值改动。」**

**⭐ 这一条解决了原先「读文件允不允许」的矛盾。**

| 能力 | 结论 |
|---|---|
| **读文件** | ❌ **不给** |
| **试卷怎么给** | ⭐ **通过系统提示词注入**（不落文件，所以没有可读的） |
| **作答在哪** | ⭐ **草稿纸**（我们给的一个文件） |
| **怎么盯** | ⭐ **监控草稿纸的哈希值改动** |

**⚠️ 关键：试卷**不落文件**，只存在于系统提示词里。因此「读文件」这条禁令不会影响它看题。**

### 4.2 完整拦截表

| 能力 | 拦？ | 理由 |
|---|---|---|
| **写文件（除草稿纸外）** | ⭐ **拦** | 改题目、改中间值、改日志 |
| **写草稿纸** | ⚠️ **允许，但盯哈希** | 只许改一次，改多次即异常 |
| **读文件** | ⭐ **拦**（已定） | 试卷不落文件，无需读 |
| **`pwsh` / `subprocess`** | ⭐ **拦** | 能绕过一切限制 |
| **web 搜索** | ⭐ **拦** | 能上网查答案 |
| **调用非本测试的工具** | ⭐ **拦** | 越权 |
| **`tools.restrict` 被调用** | ⭐ **拦** | 想自己放宽限制 |

**⭐ 草稿纸哈希监控的判据：**

```
正常：哈希变化 1 次  （写入答案）
异常：哈希变化 ≥ 2 次  （反复改答案）
    ↓
⭐ 后者立即标记，作为舞弊证据
```

## 五、提醒措辞（固定，才有据可依）

**建议措辞：**

> **⚠️ 本操作超出测试允许范围，已被拦截。请按题目要求作答；重复尝试将被判为舞弊。**

**⭐ 理由：**

| 要素 | 作用 |
|---|---|
| 「超出允许范围」 | 说清是什么问题 |
| 「已被拦截」 | 说明没有生效 |
| 「请按题目要求作答」 | **给出正确做法**，不是只罚不教 |
| 「重复尝试将被判为舞弊」 | 明确后果 |

**⚠️ 这与我被 confirm 门拦住时的提示同构 —— 那个提示会告诉我「请向用户索要 confirm」，给的是出路。**
