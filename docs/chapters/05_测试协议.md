## 5.0 为什么需要「任务叠加」

### 5.0.1 从通用场景的实际形态出发

**在通用场景中，一个人可能在照顾孩子的同时，思考两餐吃什么、近期该交的税费、以及如何修理坏掉的水管——这些任务往往需要并发处理。**

**⭐ 这里的关键是：这些任务**同时发生**，它们并不是依次做完一件再做下一件。**

**AGI 的处境与此类似：它往往需要**身兼数职**，而**不是一个 AI 照顾孩子、一个 AI 做饭、一个 AI 拖地**。**

**⚠️ 后一种设想值得单独说明，因为它是本文必须排除的一条退路：**

```
如果"通用"可以由多个专才拼接而成
        ↓
那就不需要任何单个系统具备通用性
        ↓
通用性要求就自动消解了
        ↓
⭐ 所以本文测的是【单模型】的复杂任务叠加处理能力，不是系统的拼接能力
```

**⚠️ 多 agent 协作属另文范围，本文只测单模型 —— 见第四章 §4.6 边界声明。**

### 5.0.2 从通用性推出，而不是从难度考虑

**通用人工智能之所以通用，正因为它能承担复杂任务，从而与普通 LLM 区别开来。**

**从这一点上讲，准 AGI 作为全能智能底座，必须具备复杂任务并发处理能力。**

**推导如下：**

```
① 单一任务测不出通用性
   因为通用场景里，没有任何一个任务是"干净地"单独出现的
                    ↓
② 必须把任务叠加起来测
                    ↓
   叠加之后，系统要同时维持多个议题的状态
   —— 这才是"多议题并发"下的处理能力
```

**⭐ 关键：叠加不是我们为了加难度而加的手段，而是通用性的直接要求。**

**⚠️ 如果只测单任务，测出来的能力无法外推到通用场景 —— 因为通用场景里根本不存在单任务。**

### 5.0.3 「多议题并发」在这里的具体含义

**⚠️ 术语纪律：用**并发（concurrency）**，不用「并行计算（parallel computing）」。**

**理由：并行指物理上真的同时执行（多核 / GPU）；此处指的是在同一决策过程中同时维持多个活跃议题，物理上可能交替推进。LLM 在单次前向中并不执行多件事。**

**本章中「并发」具体指：**

| 并发的是什么 | 在题目中的体现 |
|---|---|
| **多个中间状态** | 12 个节点的链，每一步都要维持当前位置 |
| **多种表征** | 文字题面 + 图像（720p） |
| **多个候选工具** | 50 个选项，其中只有 10 个可用 |
| **多次查询与计算** | 每步两次计算（求变量 + 求函数值） |

**⭐ 这四条合起来，构成「全能智能底座的多议题并发处理能力」的可测形式。**

### 5.0.4 与第四章的接口

**本章的三个难度维度，分别对应第四章的设计维度：**

| 难度维度 | 代号 | 对应维度 | 测什么 |
|---|---|---|---|
| **计算复杂度** | **L** | 能力维度 | 枚举步数 ÷ 最优步数 |
| **提示强度** | **P** | 迁移维度 | 提示依赖度、工具识别步数 |
| **语言覆盖** | **G** | 能力维度的表征独立性 | 跨语言是否仍能识别工具 |

**⚠️ 品格与维持两个维度，由题目本身的状态结构测量（见第六章），不由某一维度单独承担。**

## 5.1 Xu-AGI I1 的定位

### 5.1.0 命名

**本基准的各级测试命名为 `Xu-AGI I1`、`Xu-AGI I2`（**共两级**，见 §5.7）。**

| 部分 | 含义 |
|---|---|
| **Xu** | 提出者姓氏 |
| **AGI** | 领域标识：面向通用人工智能的准入测试 |
| **I** | **Index（指数）**：本基准最终输出的是一个**加权综合指数**，而非若干互不相关的分项得分 |
| **1 / 2** | 级别 |

**⭐ `I` 的取义不是比喻，而是产物形式：报告最终给出一个指数，由多维度成绩按权重合成。**

**⚠️ 指数如何合成、权重从哪来、如何归一，属第六章（指标与统计）的内容，本章不展开。**

**⚠️ 级别与难度的符号区分：**
- **级别**用 `I1 / I2`
- **难度维度 L** 用 `L1–L4`

**两者不要混写。**

### 5.1.1 本文发布的是第一级

> **本文发布的是本基准的第一级 Xu-AGI I1：在工具集齐备的条件下，测试系统能否从候选中识别并组合出正确路径。**
>
> **第二级 Xu-AGI I2（工具部分缺失、缺失部分须纯算）作为本框架的扩展，不在本文范围内。**

**⚠️ 只分两级，理由见 §5.7：分级本身要付论证成本，层级越多要解释的就越多。**

**⚠️ 这个限定必须写明，理由有三：**

| 理由 | 说明 |
|---|---|
| **诚实** | 不声称测了全部 |
| **可扩展** | 框架在先，级别是填进去的 |
| **不被追问未做的部分** | 明确划界，审稿人不会要求本文完成全部级别 |

### 5.1.2 Xu-AGI I1 的具体形态

```
工具      50 组，全部配备（其中 10 组正确，40 组干扰）
模型要交  哪 10 组工具、以及它们的顺序
不要求交  中间值、最终数值
判定      工具选得对不对、顺序对不对
```

**⭐ 「不要求交数值」这一点很重要：它使 Xu-AGI I1**完全绕开浮点误差问题**。**

**数值判定（含误差区间处理）留给后续级别，见 §5.7。**

## 5.4 三个难度维度

### 5.4.0 三个维度是什么、从哪里来

**⚠️ 先交代清楚，否则后面的 L / P / G 缩写看不懂。**

**本基准的难度不是一条线上的深浅，而是三个**互相独立的维度**。**

| 代号 | 名称 | 含义 | 从哪来 |
|---|---|---|---|
| **L** | **计算复杂度**（Level of computation） | 题目抽象到什么程度、路径拉得多长 | 「太简单了没意思」→ 需要分层 |
| **P** | **提示强度**（Prompt strength） | 工具的描述给多少 | 「不能明说鸡兔同笼，就像一个人不受教育，拿到扳手不知道是干嘛的」 |
| **G** | **语言覆盖**（Global languages） | 用几种语言替换变量名与工具名 | 「多语言动名词替换」＋ 联合国正式语文 |

**⭐ 三个维度是**互相独立**的，可以任意组合（例如 L1P3G2）。**

**⚠️ 它们不是等级关系。L 高的不一定 P 低，P 低的也不一定语言多。**

**⚠️ 用「维度」而不是「轴」：轴容易被误解为同一根坐标轴上的刻度，而这三者是不同的方向。**

### 5.4.1 L 维度 · 计算复杂度

| 层 | 构造 | 测什么 |
|---|---|---|
| **L1** | 裸题：直接给数值与运算 | 基线 |
| **L2** | 具象化：值嵌入情景描述 / 图像 | 抽象难度 |
| **L3** | 蒙面：函数套构造，路径拉长 | 搜索难度 |
| **L4** | 压缩：每个选项本身是压缩包 | 解压 + 搜索 |

**⚠️ 本文 Xu-AGI I1默认在 L1–L2。**

### 5.4.2 P 维度 · 提示强度

| 层 | 工具描述给多少 |
|---|---|
| **P1** | 完整行为描述（如「我住在农家大院，爱数动物的脚……」） |
| **P2** | 只说能力类别 |
| **P3** | 只有名字 |
| **P4** | 只有**输入/输出空位**（`输入 a = ?` / `输出 b = ?`），不给任何数值 |
| **P5** | 连示例都没有，调用过才知道 |

**⭐ P 维度的落点是**提示依赖度 = P1 得分 − P5 得分**。差值越大，越依赖外部提示。**

**⚠️ P4 的定案（2026-11-07 Frank）：**

> 「选用无关变量随机一个有效值替代，但更稳妥的做法是用 ab 替代，
> 输入 a 可以得到 b，我猜你在那个式子里写了函数是什么吧？
> **所以模型自己会判断输出什么。**
> 我们只需要提供 a= 和 b= 的位置，让模型输入 a 值 b 就会出来，
> 面板上在每个输入结束后会按顺序保存下模型用过的记录，以供后续出分析。」

**⚠️ 为什么不能把输入输出对摆出来：**

```
给 (2.5, 0.999999) 两个点
        ↓
模型不读描述，拟合两点就能反推函数身份
        ↓
⭐ 测的是「从数据反推函数」，不是「读懂描述」—— 与本基准主旨不符
```

**⭐ 为什么给空位就够：工具描述本来就写了函数是什么。**

```
本工具对（造型）的值执行如下变换：求一个数的误差函数值。
本工具对（造型）的值执行如下变换：求一个数自乘四次的结果。
```

**模型能从描述推出 b，然后填 a 去验证。这正是 P4 要测的能力。**

**⚠️ P4 下的交互记录（判分器数据来源）：**
每一次 `call` 都进 `ToolConsole.records`，按 `seq` 严格顺序存下
`seq / t / action / tid / x / y / ok / note`；失败的输入同样记录。
`n_call` 只数成功的真实计算，`n_nav` 数导航，`digest()` 出哈希可接哈希链。

**⚠️ 表述纪律：工具描述给的是**行为特征**，不是**语义说明**。
**不得出现「鸡兔同笼专家」这类直接点明用途的说法；只能出现「我住在农家大院，爱数动物的脚」这类可观察的行为。**

### 5.4.3 G 维度 · 语言覆盖

| 难度 | 语言集 | 依据 |
|---|---|---|
| **基础** | 中文、英文 | — |
| **中等** | 中、英、法、俄 | 联合国正式语文，六取四 |
| **高** | 中、英、法、俄、西、阿 | **联合国正式语文全集（6/6）** |

**依据：联合国六种正式语文为阿拉伯文、中文、英文、法文、俄文、西班牙文。**
**（来源：https://www.un.org/zh/our-work/official-languages ）**

**⭐ 采用该集合的理由：语言集不是本文设定的门槛，而是既有的官方定义。**

**⚠️ 德语、日语不在列，因不在六种正式语文之内，不另作解释。**

**G 维度的作用：**

```
若只在一种语言下能识别工具  →  依赖语言模式匹配
若跨语言都能识别            →  依赖结构理解
```

### 5.4.3a 链上值的命名与分类（2026-11-08）

**一条链上的值分两类，必须分开命名：**

| 类 | 前缀 | 编号 | 来源 | 给不给数值 |
|---|---|---|---|---|
| **预指派** | `A` | `A000`（唯一） | 造题时定死 | ✅ 直接给 |
| **链节自变量** | `X` | `X001`…`X010` | 上一节函数输出 × c × cn | ❌ 绝不给 |

**⭐ 每一节的结构：**

```
A000 ─f₀,c₀,cn₀→ X001 ─f₁,c₁,cn₁→ X002 → … → X010
                                              ↓
                      终值 = A000 × X001 × … × X010
```

**⚠️ 一个链节内部打包的是：函数 f、逆函数 f⁻¹、包系数 c、这一节系数 cn。
它的自变量就是这一节的输入（A000 或 X00i）。**

**⚠️ 函数编号（E###/H###）与系数编号（C##）独立，不受变量改名影响。**

### 5.4.3b 多模态维度 · 自变量图（2026-11-07）

**本基准的变量经字典替换（`groupmap.py`），题面上只剩抽象名词。**
**自变量的数值不能写在题面里 —— 题面是文字，模型能读，
那等于把答案的入口直接铺平。**

**⭐ 做法：自变量以图片形式给出，模型看图取数，再填进算式。**

```
题面：给出「誓言」这一项，其余要你自己推回
        ↓
图片：黑底白字或白底黑字，直接显示数值 -9
        ↓
模型：看图拿到 V000 = -9 → 开始反推
```

**⭐ 要点：数值只能「看到」，不能「读到」。**

**规格：**

| 项 | 设定 |
|---|---|
| **配色** | 白底黑字 / 黑底白字，**按种子随机** |
| **内容** | 自变量的数值，负号与小数点照实渲染 |
| **字体** | 无衬线粗体，字号撑满画面（实测 ≥ 340px） |
| **位置** | 中心附近小幅抖动（±4%），不固定于正中 |
| **像素** | 阈值化后只有两色，PNG 内无任何文字元数据 |
| **分辨率** | 1280×720 |

**⚠️ 小数精度：** 自变量是 float64（如 4.362814911333213），
图上按 **6 位有效数字**渲染（4.36281）。判定时用完整值比对，容差已覆盖差距。

**⚠️ 关于 OCR：** 模型若调用 OCR 工具读图，会被 DSH 的门控如实记录。
故本维度不在图侧设防 —— 绕路的痕迹记在操作日志里，由判分器处理。

**⚠️ 图形符号库（备选）：**

**本基准另备有一套基于 Unicode 图形符号库的计数题材料（`glyphlib`），
可用于构造多模态难度更高的变体。当前不使用，文中不展开其方法。**

**⭐ 当前各维度难度定位：均取较基础的设置 ——
本基准不以绝对能力难度为难模型，而以通用性、长链与维度叠加为测试重点。**

**⚠️ 种子：本维度每一步的随机（配色、抖动）均由主种子经 sha256 派生，
逐条记入种子台账（`seedlist.py`），台账可逐字节重建图片。见 §5.4.6。**

### 5.4.4 三维度与「任务叠加」的关系

**⚠️ 三个维度并非各自独立地增加难度，而是**叠加**的：**

```
L 维度叠加  →  抽象层级在变
P 维度叠加  →  可用的语义信息在减少
G 维度叠加  →  表层语言在变
              ↓
  三者同时作用时，系统要在一个决策过程中
  同时维持多个表征与多个活跃议题
              ↓
  ⭐ 这才是"多议题并发"的完整形态
```

### 5.4.5 ⭐ 当前难度定位与可提升空间（2026-11-07 Frank 定）

> **⚠️ 本节回答一个必然被问到的问题：「你们的难度够吗？」**
> **完整论证见 `程序设计与实现说明.md` §8f.1b 与 §8f.1c。**

### 一、难度是多维的，本文不追求单一维度的极限

**本文的难度不是一条线上的深浅，而是多个方向上的综合设定。**
**当前设定落在较基础的位置，各维度保持相对均衡，而非在某一维度上推到极限。**

| 维度 | 当前设定 | 可提升空间 |
|---|---|---|
| **高等函数** | 只给**单个值**用于推演 | 可要求系统自行在区间内定位 |
| **工具完整性** | **给出全部工具选项** | 可只给部分，要求系统自行补足计算 |
| **运算结构** | **仅在 y 值之间使用乘法** | 可在预指派链间复合嵌套复杂函数 |
| **取值范围** | **标量** | 可引入区间、向量、矩阵 |
| **抽象层** | **中英双语 + 图像** | 可加入音频、视频、传感器数据、逻辑判断推理题 |

**⚠️ 关于「取值范围」这一行的说明：**

**工具筛选的首要维度是可计算性 —— 输出须为标量，能直接参与后续运算。**
**输出为区间、向量、矩阵等非标量结构的函数，本文排除在外。**

**⭐ 这不是因为它们不重要，而是因为本文当前的题目形式要求标量。**
**若把这些作为待求量让系统往回推，难度会显著上升 —— 那是另一个测试层次。**

### 二、工具选择本身就是难度取舍

**本文的工具集是多维筛选的结果，其中包含对难度的权衡：**

```
可逆性     →  反推唯一，否则无法判分
标量性     →  可直接参与运算
真实存在   →  取自公开科学计算库，不是人造的壳
有计算量   →  排除平凡函数
领域典型   →  使「为何选它」无需另行论证
```

**⭐ 这五条同时作用，选出的是一套"适合当前测试形式"的工具，
而不是"最难的"或"最全的"工具。**

### 三、本测试的定位（关键表态）

**⚠️ 以下两句应与 §8f.7、§8f.8 一起读，它们共同构成本文的难度立场：**

> **本测试目前的难度设定较为基础，未来可提升的空间较大、方向较多。**
>
> **本基准测试仅为验证论证逻辑，以及提供一种验证 AGI 能力的基准测试设计思路。**

**⭐ 换句话说：本文交付的是**设计思路与可执行的框架**，
不是「一个足够难的基准」。难度上限由框架允许，
具体档位是本文给出的一个可用起点。**

**⚠️ 表述纪律：**

| ❌ 不写 | ✅ 写 |
|---|---|
| 「本基准难度不足」 | 「当前难度较为基础，可提升空间较大」 |
| 「我们故意做简单了」 | 「难度是多维的，本文选择均衡的基础设定」 |
| 「以后会做难的」 | 「框架允许在上述各维度上提高难度」 |

### 5.4.6 ⭐ 随机性与种子库（防「猜对」机制）
> **完整说明见 `程序设计与实现说明.md` §8f.1c。**

### 一、所有题目特征均可随机生成

| 可随机的对象 | 随机范围 |
|---|---|
| **工具（函数）** | 从可逆函数池中随机抽取 |
| **链长与结构** | 由配置决定，各层函数随机组合 |
| **节点值** | 由锚点与系数逐层算出，随种子变化 |
| **干扰值** | 随机生成，且与所有节点保持区分度 |
| **选项顺序** | **每次随机置换** |
| **工具呈现顺序** | **每次随机置换** |
| **变量名 / 工具名** | 从词库中随机取词替换 |
| **语言** | 中 / 英（可扩展至联合国六种正式语文） |
| **图像表征** | 由结构生成，随参数变化 |

### 二、种子库设计为可更改

**⚠️ 本文的随机性不是写死在代码里的，而是从可替换的"种子库"取用的。**

| 种子库 | 内容 | 可否替换 |
|---|---|---|
| **语言词库** | 中 / 英动名词表 | ✅ 可扩展至其他语种 |
| **抽象层素材库** | 图像表征模板 | ✅ 可加入音频、视频等 |
| **数学种子库** | 函数集与参数表 | ✅ **随函数集变化调整** |

**⭐ 方法论意义：**

> **若随机源可替换，则基准不会因为某一套词表被模型记住而失效。**
> **词库更新后，同一数学结构会以全新的表层形式重现。**

### 三、选项顺序随机化：防的是「位置偏好」

```
若正确选项总是集中在某些位置
→ 模型可能学到「选第 3 个」这类与能力无关的策略
→ 成绩不再反映能力
```

**本文的处理：**

```
① 选项值随机置换（值与步数标记同步打乱）
② 工具呈现顺序随机置换
③ 正确项在选项中的位置分布，不施加任何人工约束
```

**⚠️ 实现现状（如实说明）：**

**选项顺序与工具顺序的随机置换**已实现**（`vectorform.pick_options_gpu` / `build_tools_gpu`）。
**语言词库替换与图像生成尚未接入主流程**（见 `程序设计与实现说明.md` §13.2 第 1、2 条）。**

## 5.4.7 ⭐⭐ 工具的呈现：身份可换，内容不变

> **⚠️ 本节回答一个设计问题：工具该以什么身份出现在模型面前？**
> **实现见 `skins.py` 与 `toolconsole.py`；完整记录见
> `开发日志\D2026-11-07_模块化抽象与工具控制台.md` §2.3。**

### 一、工具的三种合法身份（Frank 2026-11-07 定）

> 「工具可以说自己是工具，可以说自己是擅长某方面的专家，
> 可以说自己是懂什么计算的热心人，这都符合 AGI 在通用场景下的定义。
> 总之需要过滤信息，经过运筹计算，判断最优效率的路线和备选路线。」

**⭐ 这一条把「句式多样性」从文字游戏提升为**被测能力**：**

```
真实通用场景里，人面对的信息就是杂乱的：
    · 有的工具写得很专业（说明书式）
    · 有的自称专家
    · 有的写得很随意（热心人口吻）
    · 有的信息还不全（只说「已知 X 求 Y」）

⭐ 模型要能从这些不同口吻里，筛出有用信息，
   经过运筹计算，判断最优效率的路线和备选路线。
```

**⚠️ 所以：身份可以换，「干什么」必须一致。**

### 二、四组口吻（共 13 套语法）

| 组 | 口吻 | 例（函数 = 平方） |
|---|---|---|
| **A** | 工具口吻（中性、说明书式） | （小红）的值为：由（小明）的值求得一个数自乘两次的结果。 |
| **B** | 专家口吻（自称擅长） | 我擅长处理（小明）的值到（小红）的值的换算，做法是：求一个数自乘两次的结果。 |
| **C** | 热心人口吻（口语、随意） | 懂一点这个：把（小明）的值变成（小红）的值，靠的是 求一个数自乘两次的结果。 |
| **D** | 信息不全口吻 | 已知（小明）的值，怎样才能得到（小红）的值？做法是 求一个数自乘两次的结果。 |

### 三、⚠️ 三条不可违反的约束

**① 名词后带「的值」**

```
❌ （小明）→（小红）
✅ （小明）的值 → （小红）的值
```

**⭐ 让模型知道那是一个数，不是一件物体。**

**② 不说「粒子专家」，要说「计算粒子运动什么内容的专家」**

> Frank：「不能说是粒子专家，要说是计算粒子运动什么内容的专家，
> 因为每个公式内容都不同。」

**③ 高等函数也要尽量描述，不用 `f` 代替**

> Frank：「高等函数能描述的要尽量描述，尽可能的不要用 f 表示，没办法就算了。」

**⚠️ 实测：74/74 个函数全部用自然语言描述，零个 `f`。**

### 四、⚠️ 与变量替换的区别（本节最重要的一条）

> Frank：「这点与名词替换不同，变量可以换为所有名词，
> 因为变量只是一个值的指代，其本身可以无意义。」

| 部件 | 能不能乱换 | 原因 |
|---|---|---|
| **变量** | ✅ **随便换名词** | 只是「值的指代」，本身无意义 |
| **函数** | ❌ **必须符合特征** | 换了特征，模型判断不出它干什么 |

## 5.5 判定方式（2026-11-08 重写）

> **⚠️ 本节整节重写。旧版判「选了哪 10 组工具、顺序对不对」—— 那是旧形态。**
> **现形态下，模型要交的是「10 个 y 的编码」，工具与顺序不再是被判对象。**

### 5.5.1 模型交什么

**题面给出的形式是：**

```text
A000 × [ 空1 ] × [ 空2 ] × … × [ 空10 ] = Z
```

**模型要交的是 10 个选项代码，例如：**

```text
Y-O007, Y-O013, Y-O021, Y-O004, Y-O056,
Y-O032, Y-O011, Y-O045, Y-O028, Y-O003
```

**⚠️ 交的是编码，不是自己算出的数值。**

**理由：编码在出题时已定死，模型只能"从选项里挑"，不能"自己编一个数"。**
**这一点直接堵死了「乱填一个数碰运气」的路径。**

### 5.5.2 判什么

| 项 | 判否 | 说明 |
|---|---|---|
| **选的 10 个 y 对不对** | ✅ 判 | 与出题时的真值集比对 |
| **连乘等不等于 Z** | ✅ 判 | 独立复核 |
| **模型报出的 y 数值** | ❌ 不判 | 数值由我们反推，模型不必给出 |
| **模型走的中间步骤** | ❌ 不判 | 不要求报过程 |

**⚠️ 两条判据同时成立才算对：**

```text
① 集合相同：模型选的 10 个编码 == 出题时的 10 个真值编码
② 数值闭合：A000 × Y1 × … × Y10 = Z
```

**为什么两条都要：**
- **只有 ①** → 不够，模型可能报对编码但算错数，说明它并未真正求解
- **只有 ②** → 不够，干扰项里可能存在别的组合也能乘到 Z（本文已排除，但判据应独立成立）

### 5.5.3 四种判定结果

| 判定 | 含义 | 归入 |
|---|---|---|
| **完全正确** | 10 个编码全对，且连乘等于 Z | 能力 |
| **部分正确** | 对了一部分；命中数 / 10 记为**选项命中率** | 能力 |
| **编造** | 报了不存在的编码，或称已完成而连乘不等 | **品格（不可信）** |
| **绕路** | 试图通过枚举、猜位置、试错拼凑而非求解 | **品格（绕路）** |

**⚠️ 四种是**同一次答题的四种结果**，不是难度级别。**

**⭐ 「编造」与「绕路」是**否决项**，不是计分项 —— 见第四章 §4.5。**

### 5.5.4 选项命中率

```text
选项命中率 = 选对的编码数 ÷ 10
```

**⚠️ 分母恒为 10，由出题时的预指派构造给出，不是事后推断。**

**⚠️ 这个指标与旧版的「工具命中率」不是同一个东西。**
旧版量的是"会不会挑工具"，新版量的是"能不能从 60 个里挑出正确的 10 个"。

### 5.5.5 ⚠️ 与「唯一性」的关系

**本题的判分依赖一条性质：60 个候选里，只有一个 10 元组合能让连乘等于 Z。**

**这条性质由 §5.9.4 的干扰项构造保证（干扰项与 2047 个组合乘积全部不同）。**

**⭐ 因此「判分」与「题目构造」是同一件事的两面 —— 不能分开论证。**

## 5.6 唯一性与防猜

> **⚠️ 本节为设计思路，现行实现见 §5.9.4（2047 个组合乘积）与 §5.5.3（绕路判据）。**
> **随机性的具体作法已在新版实现，本节保留论证。**

### 5.6.1a ⭐ 选项位置的约束打乱（2026-11-09）

**⚠️ 光把选项随机打乱还不够 —— 真值不能扎堆，也不能留在原位附近。**

**本文对展示顺序施加三条约束：**

```text
① 60 个选项分 6 组，每组 10 个位置
② 每组里的真值个数 ≤ 3
③ 打乱后与【原始顺序】同位相同的个数 ≤ 18（30%）
```

**⚠️ 约束②的理由：**

**60 个选项里只有 10 个真值。若真值集中在前几组，模型只需在前半段搜索即可。**
**每组 ≤ 3 保证真值分散在整张卷面上。**

**⚠️ 约束③的理由：**

**原始顺序是"前 10 个是真值"。若打乱后仍有大量选项留在原位，模型可以按位置猜。**
**与原始顺序的重合率 ≤ 30%，等于要求至少 70% 的选项移动了位置。**

**满足约束的前提下，每种合法排列等概率 —— 不做额外的"最分散"处理。**

**实测：50 次打乱全部成功，平均重抽 1.0 次，与原序的最大相似度 5.0%。**


### 5.6.1 唯一性的三层保证

| 层 | 手段 |
|---|---|
| **① 构造** | 答案先定，路径由逆运算反推 |
| **② 数值** | 中间值互异，节点两两不同 |
| **③ 干扰** | 干扰项与路径数值上不连通 |

**⭐ 三层合起来：模型无论怎么试，只有那 10 组能连通到终点。**

### 5.6.2 防位置猜测

**每 10 个连续选项中，正确项不超过 3 个（滑动窗口）。**

**⭐ 没有这条，模型可以靠**位置规律**蒙对，凑数即绕过认知。**

### 5.6.3 防暴力枚举

**⚠️ 这一点与 §5.0 的论证直接相关：**

| 为什么不可暴力 | 量级 |
|---|---|
| 组合爆炸 | C(50,10) ≈ 1.03 × 10^10 |
| 上下文占用 | 每次试错均消耗上下文 |
| 三层随机 | 工具随机 / 题目随机 / 变量需读题求 |

**⭐ 应为「结构上不可能」，而非「难」。**
**⭐ 这一点同时回答了「凭什么测通用而非专用」：在这个空间里，暴力路径不存在。能通过的，只能是学会使用工具的那一条。**

## 5.7 两个级别

> **⚠️ 本节为整体设计思路，与现行实现一致，保留。**


**⚠️ 2026-11-06 修订。原设计分三级，现改为**两级**。**

**理由（Frank 2026-11-06 原话）：**

> **「我们不需要分太多级，我不清楚他们的意图，但**分级越多你越需要解释，为什么这么分**？我们做两级区分比较好讲。」**

**⭐ 也就是说：分级本身要付论证成本，层级越多，要解释的就越多。两级够用，就不要再分。**

### 5.7.1 ⚠️ 区分级的判据：工具完备程度

**⚠️ 这个区分很重要，因为工具的完备程度决定了**测的到底是什么**。**

| 情形 | 强制被测系统做什么 |
|---|---|
| **工具全部提供** | **不强制复杂计算** —— 只需在大量候选中识别并组合工具 |
| **工具部分缺失** | **缺失部分必须由系统自行计算** —— 此时才强制复杂计算 |

**⭐ 一句话：工具全给，测的是能不能认出来、能不能串起来；工具不全给，才逼它自己算。**

**⚠️ 若不作这一区分，会产生误读：以为「给了工具」就等于「要求系统会复杂计算」，而事实上恰恰相反。**

### 5.7.2 两级

| 级别 | 工具配备 | 被测内容 | 本文 |
|---|---|---|---|
| **Xu-AGI I1** | **50 组齐备** | 识别并组合工具 | ✅ **本文发布** |
| **Xu-AGI I2** | **部分缺失，缺失部分须纯算** | 识别 + 组合 + **补足计算** | ❌ 不在本文范围 |

**⭐ Xu-AGI I2 的设计意图（Frank 原话）：「又要会用工具，会省上下文，又要会计算，这才是地狱考核。」**

### 5.7.3 ⚠️ Xu-AGI I2 的技术障碍（已识别，未解决）

连乘会放大误差区间
    ↓
必须规定每一轮运算到小数点后几位
    ↓

**⚠️ 该问题本文不处理。Xu-AGI I1 通过「不判数值」完全避开。**

**⚠️ 附带用途（本文未实现）：I2 天然是**测「不可信」否决**的场景 —— 纯算时系统可能编造一个「看起来像」的数，比对精确值即暴露。**

## 5.9 ⭐ 生成流程与可实现性（2026-11-08 重定）

> **本节替换旧 §5.2 的题目结构与旧 §5.3 的工具集。旧节保留作历史，正稿以本节为准。**

### 5.9.1 一道题由什么构成

```text
首值   A000
   ×
十个链值  Y001 … Y010
   =
尾值   Z        Z = A000 × Y001 × … × Y010
```

**60 个候选 = 10 个真值（Y001…Y010）+ 50 个干扰项。**

**⚠️ A000 和 Z 是条件，直接给出数值，不进候选池。**
它们不需要用 x 去推算——它们是已知量。

### 5.9.2 每个选项带什么

```text
O001    x = 25.5781382677
        f1 = exp   c1 = 100
        f2 = pow2  c2 = 100
        题面：  Y = (exp(((X)^2) ÷ 100)) ÷ 100
```

**⚠️ 题面上不出现：**
- **y 的值**（模型要求的东西）
- **函数的编号**（内部记录用，不进题面）

**⚠️ 题面上出现：**
- **x 的值**
- **y 的编码**（`Y-O001`，模型填答案时用）
- **两个函数名与两个系数**

### 5.9.3 ⭐ 随机性：60 个选项必须各不相同

**每一选项独立抽取：**

```text
f1  ← 从 58 个可用函数里等概率抽
f2  ← 从 55 个可用函数里等概率抽（后层另有一张名单）
c1、c2 ← 各自独立算出来
x   ← 由上述三者决定
```

**⚠️ 本文明确禁止一种做法：60 项共用同一对函数。**

**理由：** 共用同一对函数时，60 个选项的式子完全相同，模型的"阅读量"骤降，测的就不再是同一种能力。**为省一点生成时间而牺牲这一条，是本末倒置。**

**具体做法：组合池，抽走不放回。**

```text
合法函数对 = {(f1, f2) | f1 在可用池, f2 在可用池, 不在禁止搭配里}
           ≈ 58 × 58 ≈ 3300 种

生成 60 项时，每项从【尚未使用】的组合里随机抽
用掉即移出池
```

**⇒ 同一道题内，60 个选项的函数对各不相同。**

**⚠️ 组合池只在单道题内有效**，跨题重新开始 —— 否则池子会越用越小。

### 5.9.4 ⭐ 干扰项：2¹¹ − 1 个组合乘积

**11 个元素（A000、Y001…Y010）的非空子集乘积共 2¹¹ − 1 = 2047 个。**

**⚠️ 乘法没有顺序，是组合不是排列。**

**干扰项要求：和这 2047 个乘积中的每一个都不同。**

**实测（`trace/`，3481 对函数的枚举运行）：**

| 项 | 值 |
|---|---|
| 禁止集合大小 | 2047 |
| 每批干扰项数 | 50 |
| 与禁止集合相撞 | **0** |
| 干扰项彼此重复 | **0** |

**⚠️ Z 本身就在禁止集合里**——它是全部 11 个元素的乘积。

### 5.9.5 ⭐ 函数池：采用哪些，排除哪些

**59 个可逆函数中，本文采用 58 个，排除 1 个。**

| 项 | 数 |
|---|---|
| 库内可逆函数 | 59 |
| 本文排除 | **1**（`erfcx`） |
| 本文采用 | **58** |

**⚠️ 排除的底层原因：判定区间过窄，系数也无法把值搬进去。**

**每个函数有两个区间：**

```text
search    它能接受什么输入
y_range   它能产出什么输出
```

**反推时，`c · y` 必须落进 `y_range`——这是 `f⁻¹` 的输入。**
**若 `y_range` 的宽度不足一个数量级，任何 `±10^k` 都跨不过去：**
**乘大了超上界，乘小了掉下界，中间没有可用的档位。**

**此时加入 `2^m` 细调也可能不够 —— 区间窄到一定程度，7 个细分档仍覆盖不了。**

**`erfcx` 即属此类：它的值域虽宽，但在整个值域上 `f⁻¹` 均无法定位到有效解**
**（在值域上等距取 8 个点，全部返回 `nan`）。**
**这类函数即使系数能搬进值域，反推这一步本身也不成立，因此不进入题库。**

**其余 58 个函数在同样测试下全部 8/8 通过。**

**⚠️ 本文的定位：**

**本基准的目的是测试，不是研究数学函数本身的性质。**
**函数只是题目的材料，它们的解析性质、数值行为、特殊值分布不在本文讨论范围内。**
**本文只做一件与函数有关的事：判断它能否被稳定地用于构造与反推，能则采用，不能则排除。**
**排除之后不再追究"为什么这个函数不行"——那是数学分析的工作，不是基准设计的工作。**

### 5.9.5a ⭐ 精度控制：让更多函数可用

**一个函数能不能用，不只取决于它本身，还取决于系数能不能把一个值搬进它的值域。**

**本文的系数形式（见第四章 §4.11.3）：**

```text
c = ±1 × 10^k × 2^m

    k ∈ [-30, 30]     调数量级
    m ∈ {0, ±1, ±2, ±3}  半个数量级内微调
```

**⚠️ `2^m` 的作用：**

**有些函数的值域宽度不足一个数量级（例如 `ellipe` 的值域是 `[1.07, 1.505]`，宽 0.45）。**
**只靠 `10^k` 跨越不过去 —— 乘 1 太大，乘 0.1 太小。**
**加入 `2^m` 后，可以在两个相邻数量级之间再切出 7 档，把这类函数纳入可用范围。**

**⚠️ 为什么用 `2^m` 而不是任意实数倍数：**

```text
2^m 在二进制浮点里是【精确】的（整数次幂）
任意实数倍数会引入额外舍入
```

**⚠️ 顺序安排：`m = 0` 排在候选表最前，`|m| = 1,2,3` 依次往后。**
**这样"取第一个合格的"自然是"最温和的那个"—— 能不用细调就不用。**

**实测效果：**

| 系数候选 | 数量 | 因"缩放不进值域"而失败的组合 |
|---|---|---|
| 仅 `±10^k` | 122 | 5 次 / 150 |
| 加 `2^m` | 854 | **1 次 / 150** |

### 5.9.5b ⭐ 精度隔离带：干扰项与中间体保持距离

**⚠️ 本文对所有选项设一个精度上限：**

```text
单个选项的往返相对误差  ε ≤ 1e-9
```

**超过这个上限的选项不采用。实测 60 项的真实误差在 `1e-16 ~ 1.2e-10` 之间，远低于上限。**

**⚠️ 但真正的风险不在单个选项，而在"接近"。**

**如果某个干扰项的值与某个真值（或某个组合乘积）相差极小，模型即使精度不够也能"蒙"对 —— 题目就失效了。**

**本文对干扰项设置两道隔离：**

```text
① 与 2047 个组合乘积隔离

    每个组合乘积的精度带 = 参与元素的 ε 之和（误差累积）
    要求：|干扰项 − 组合| > |组合| × tol + K × 精度带

② 干扰项彼此隔离

    要求：|干扰项 − 已选干扰项| > |已选| × tol + K × (ε + ε)
```

**其中 K 为安全倍数，本文取 10。**

**⚠️ 为什么组合乘积的精度带要**累加**：**

**若 a 的相对误差为 εₐ，b 的相对误差为 ε_b，则 a·b 的相对误差约为 εₐ + ε_b。**
**11 个元素全乘起来，误差带是 11 个 ε 之和。**

**⚠️ 因此隔离带必须按"参与元素的个数"计算，不能用一个固定值。**

### 5.9.6 ⭐ 通过率：实测数字

**单次构造（随机抽一对函数 + 随机 y）的成功率，随修正逐步提升：**

| 阶段 | 成功率 | 做了什么 |
|---|---|---|
| 初版 | 62.1% | — |
| 修区间余量 | 79.4% | 按比例内缩，而非按总宽 |
| 加 ban 名单 | 91.3% | 剔除 4 个函数 |

**⚠️ 本文如实报告这三个数字，而不是只报最后的。**

**理由：后两个数字是前一个数字被证伪之后得到的。只报 91.3% 会掩盖"结构在初版时是错的"这一事实，而后者恰恰是本文最该说明的部分。**

```text
40 次全失败的概率 = (1 − 0.913)^40 ≈ 10^-44
```

### 5.9.8 ⭐ 题面的表达方式（2026-11-09）

**题面不是一个字符串拼出来的，而是先搭结构、再展开。**

**⚠️ 为什么不用字符串拼接：**

**拼接时无法判断"这个位置该不该加括号"——** 只能看生成结果里有没有括号，而那时已经晚了。
**结构化的做法是：每个节点自己知道自己的边界，括号由节点类型决定。**

#### 一、两种模块

```text
识别层   从函数总表（带编码）认出「这是哪个函数」
         并取出它的两个槽位：
             表达式槽位（参数照给）
             描述槽位（参数已在名字里）
展开层   按节点类型展开成文字
```

**识别靠函数总表，不靠猜字符串形态。**

#### 二、表达式与描述分离

**同一个函数在题面上有两种合法写法：**

| 写法 | 用在哪 | 参数 |
|---|---|---|
| **表达式** | 英文；或中文名未说明参数时 | 照模板给出 |
| **描述** | 中文且名字已说明参数时 | 不再重复给 |

**例：**

```text
hypot     描述「与一点五的平方和开方(香蕉)」    参数已在名字里
          表达式「hypot(香蕉, 1.5)」          参数照给

expn      描述「二阶指数积分(香蕉)」           阶数已在名字里
          表达式「expn(2, 香蕉)」             参数照给

betaln    描述「贝塔函数取自然对数(1.5, 香蕉)」 名字没说参数，照给
          表达式「betaln(1.5, 香蕉)」
```

**⚠️ 为什么两种语言不一样：**

**英语的简短函数名（`expn`、`iv`）本身不承载阶数信息，参数必须写出来才无歧义。**
**中文描述可以把这个信息放进名字里（「二阶」「I₀」），参数就不必重复。**
**这不是规则不一致，是因为两种语言的函数名承载的信息量不同。**

#### 三、括号：按节点类型只加一次

**表达式节点有三种：**

```text
Var   一个变量                  渲染成一个词       自带边界
Fun   函数调用                  渲染成 名字(参数)  自带边界
Bin   二元运算（本文只用到÷）    渲染成 左 ÷ 右     不自带边界
```

**⚠️ 括号规则：只有 `Bin` 节点被嵌进别处时，才需要包一层。**

**⚠️ 模板自带括号时（如 `(%s)^2`）不再额外包。**

**⇒ 每个模块或模块集最多被包一次。**

#### 四、验证结果

**5 个随机种子 × 60 项 = 300 项：**

| 检查 | 结果 |
|---|---|
| 每道题出满 60 项 | 5/5 |
| **数学验算（按题面式子算回 y）** | **0 错** |
| 括号配对 | 0 不配对 |
| 10 个答案连乘 = Z | 误差 0.0e+00 |
| 每组真值 ≤ 3 | 5/5 符合 |

#### 五、中间态的构成

**一道题在封包之前的完整内容：**

| 项 | 内容 |
|---|---|
| 条件 | `A000`、`Z` |
| 每个选项 | 代码、x 的值、x 的词、y 的编码、y 的表达式 |
| 词的语种 | 中英混编，全局不重复 |
| 答案 | 10 个选项代码（模型要填的） |

**⚠️ 还缺一项：x 的值目前是数字，未做图案化（第二层抽象）。**
**加上图案后即可封包成完整考卷。**

### 5.9.9 ⭐ 答卷器与交互方式（2026-11-09）

**试卷不只是一段文字。模型需要一个能动手的地方。**

#### 一、为什么要有答卷器

**如果只把题目写成一段话，模型只能"说出来"。**

**但本文要测的不是"能不能说"，是"能不能算对"。**
**算对需要工具，交卷需要明确的动作，判分需要可核查的记录。**

**⇒ 答卷器 = 控制台最外层。它只显示试卷、选项和工具，不显示任何内部信息。**

#### 二、一个选项 = 一个计算器

**60 个选项配 60 个计算器。**

```text
输入一个值 x
    ↓
y = f1( f2(x) ÷ c2 ) ÷ c1
```

**⚠️ 与出题时的算法完全一致**（出题时用反函数从 y 求 x，这里用原函数从 x 求 y）。
**实测误差 3.6e-16。**

**模型要做的事：**

```text
① 从图里读出 x
② 用对应计算器算出 y
③ 找 10 个 y，使 A000 × Y × … × Y = Z
④ 填编号，交卷
```

#### 三、页面结构

```text
首页
 ├── 试卷     展开复查（题目已注入上下文，这里是为了能重看）
 ├── 计算器   60 个工具列表
 │    └── 单个计算器   看式子 + 输入 + 输出
 └── 答卷     10 个格子 + 填 / 改 / 清 / 交卷
```

**⚠️ 除首页外，每个页面都能返回。**

#### 四、工具清单

| 工具 | 参数 | 作用 |
|---|---|---|
| `show_paper` | — | 显示试卷（备用路线） |
| `list_tools` | — | 列出 60 个计算器 |
| `open_tool` | `pid` | 切到某个计算器 |
| `calc` | `pid`, `x` | 输入值 → 输出值 |
| `show_answer` | — | 看答卷当前填了什么 |
| `fill` | `pid` | 填一格 |
| `submit` | — | 交卷 |

**⚠️ 工具参数只接受编号与数值两种形态。**
**没有 shell、没有文件写入、没有网络 —— 每一次调用都能被完整记录与复核。**

#### 五、全部交互可追溯

**任何操作都经过同一个记录入口，无法绕过：**

```text
record = {序号, 相对时间, 动作, 选项编号, 输入值, 输出值, 是否成功}
```

**交卷时只告诉模型"对/不对"与连乘的相对误差，不告诉它哪一个错。**

**记录以 `console.log` 与封包一起落盘，并附 SHA-256 摘要。**

#### 六、实测数字

| 项 | 值 |
|---|---|
| 单次计算延迟 | 0.2 ~ 12 ms（均值 1.8 ms） |
| 工具清单大小 | 1679 字节 |
| 60 项复算 | 0 错，最大相对误差 3.95e-10 |
| 出题耗时 | 约 28 秒 |

#### 七、问卷编号

**每次考试一个唯一编号：**

```text
EXAM-<种子>-<YYMMDD>-<HHMMSS>
例  EXAM-20261109-261109-174458
```

**试卷、题目、选项、图、记录，全部挂在这个编号下面。**
**重新生成就是新编号，不会覆盖也不会混淆。**

**⚠️ 交付是单向的：出卷器把考试目录送到模型侧。**

**模型侧不回传任何东西 —— 唯一的回流是答卷器里的交互记录，那是我们自己留在本地的痕。**
