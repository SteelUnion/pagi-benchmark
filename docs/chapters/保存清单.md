# 保存清单

> **2026-11-07 建。每次跑测试、改代码、出结果之前先看这份。**
>
> **⚠️ 这份清单是「必须保存什么」，不是「可以保存什么」。**
> **漏存的东西，事后没法补 —— 因为随机性和中间量不会重来。**

---

## 〇、为什么要有这份清单

**⭐ 三个真实教训：**

```
① 昨天汇报「快照包 74 个，失败 3 个」，
   三小时后重跑变成「失败 2 个」——
   因为自检种子用 hash()，每次进程不同。
   → 数字报出去了，但复现不了。

② 早期测试只记了「通过率」，
   没记当时的 y 窗口、系数、中间值。
   后来要查「为什么这一轮崩」时，什么都查不到。

③ 选项生成的三个待定问题，讨论了一整天，
   结论散在对话里，压缩上下文后就只剩一半。
```

**⭐ 结论：能重算的不用存，不能重算的必须存。**

---

## 一、⭐ 六类必须保存的内容

### 1.1 【硬数据】原始输出 —— 必存

| 项 | 格式 | 位置 | 说明 |
|---|---|---|---|
| **测试日志** | `.jsonl` 逐行 | `基准\logs\` | 每轮/每样本一行，不覆盖 |
| **样例题面** | `.txt` | `基准\logs\` | 生成的题面原文 |
| **诊断结果** | `.jsonl` | `基准\logs\` | 每个包的实测区间、误差 |

**⭐ 硬性要求：**

- **文件名带时间戳**：`roundtrip_v5_20261106-213239.jsonl`
- **只增不改**：同一次测试重跑 = 新文件，**不覆盖旧文件**
- **每行一条记录**，不打包成大 JSON

**⚠️ 为什么用 jsonl 不用 json：**
中途崩了，前面已写的行还在。整份 json 崩了就全没了。

### 1.2 【硬数据】复现必需的参数 —— 必存

**⭐ 这些参数不存，结果就是一次性的：**

| 参数 | 为什么必须存 |
|---|---|
| **随机种子** | 不存种子，随机序列没法重现 |
| **样本数 n** | 同样的通过率，n=10 和 n=2000 意义完全不同 |
| **链的组成** | 哪几个函数、什么顺序 |
| **每步系数 cn** | 尤其是带负号的、非 1 的 |
| **y 的取值范围** | 窗口不同，结果不可比 |
| **判定容差** | 1e-9 还是 1e-6，直接决定算不算过 |

**⭐ 已有实现（`test_roundtrip.py` 的 jsonl 已含）：**

```json
"chain": {"names": [...], "codes": [...], "coefs": [...], "coef_codes": [...]},
"y_window": [...], "y_vals": [...], "x_vals": [...]
```

**⚠️ 但缺 `seed` 和 `tol` 两个字段 —— 待补。**

### 1.2b 【硬数据】图片题面的复现参数 —— 必存（2026-11-07 新增）

**⚠️ 图片题面比纯文字多一层不可复现的风险：Unicode 规定了码位与名称，
但**画成什么形状由字体决定**。同一码位，换字体就是另一种画法。**

| 参数 | 为什么必须存 |
|---|---|
| **随机种子** | 决定图案、个数、配色、语言 |
| **图案码位** | `U+25B2` 这类，不是名字（名字可能重名或改过） |
| **图案个数 n** | 1..20 |
| **配色** | `light` 白底黑图 / `dark` 黑底白图 |
| **问句语言** | zh / en |
| **字号** | 自动撑满，实际取到的像素值 |
| **⭐ 字体文件** | `C:\Windows\Fonts\seguisym.ttf` 这类**完整路径** |
| **⭐ 字体版本** | 字体文件的 SHA-256 —— **不存这个就无法复现字形** |
| **Unicode 数据版本** | 固定 16.0.0，不用 latest |
| **画布尺寸** | 1280×720 |

**⭐ 一句话：文字题面存种子就够，图片题面还得存字体。**

```python
# 落盘示例
{"seed": 20261107, "cp": "U+25B2", "count": 7, "style": "light",
 "lang": "zh", "font_size": 76,
 "font_file": "C:/Windows/Fonts/msyhbd.ttc",
 "font_sha256": "...", "unicode_version": "16.0.0",
 "canvas": [1280, 720]}
```

### 1.2b2 【约定】值的命名 —— 预指派 vs 链节自变量（2026-11-08）

> **Frank：「必须要在核心配置文件里面，说明预指派的值跟单个链节包中
> 自变量值命名的特征以及如何区分。」**

| | 预指派 | 链节自变量 |
|---|---|---|
| **前缀** | `A` | `X` |
| **例子** | `A000` | `X001` … `X010` |
| **个数** | 1 个（只有起点） | k 个（每节一个） |
| **来源** | 造题时定死 | **上一节函数的输出 × c × cn** |
| **给不给数值** | ✅ 直接给 | ❌ 绝不给 |
| **怎么呈现** | 黑白数字图 | **文本 + 图片两次抽象** |
| **抽象维数** | 0 | **2** |

**⭐ 如何区分（一眼可辨）：**

```
A###  →  这个值是「给的」，模型一看图就知道
X###  →  这个值是「算出来的」，模型必须自己推
```

**⚠️ 不要用编号连续性区分** —— 那样要记住「A000 与 X001 有没有关系」。
**前缀不同则不需要记。**

**⚠️ 代码里只走 `module.var_pid(i)` 生成，不要在别处手写前缀。**

**⭐ 多模态抽象维数 = 2（`config.MODALITY_DIMS`），文字与图片等权各 1/2。**

### 1.2c 【硬数据】种子台账 —— 每一步都要能查

> **Frank 2026-11-07：「我们目前所有维度生成的每个步骤都应该保存种子。」**

**⚠️ 不是「存一个主种子就够」—— 要从主种子能还原出**每一步**用的子种子。**

**做法（`seedlist.py`）：**

```
主种子
  ↓ sha256 派生（⚠️ 不用 hash()，它每次进程不同）
  ├─ derive(seed, 'problem', i)          第 i 题的链
  ├─ derive(seed, 'problem', i, 'tool')  第 i 题的工具池
  ├─ derive(seed, 'problem', i, 'var')   第 i 题的变量命名
  └─ derive(seed, 'problem', i, 'figure') 第 i 题的数字图
```

**⭐ 派生规则固定：同一主种子 + 同一步骤名 → 永远同一子种子。
改了后面某一步的实现，前面几步的种子不受影响。**

**台账字段（每条记录都要能重建该步）：**

| 字段 | 内容 |
|---|---|
| `dim` | 维度名（problem / tool / var / skin / hint / figure / glyph / lang / judge） |
| `step` | 步骤路径，如 `problem/3/figure` |
| `master` | 主种子 |
| `seed` | 这一步实际用的种子 |
| `out` | 这一步的可复现产出（见下） |

**各维度的 `out` 至少要有：**

| 维度 | 必须记 |
|---|---|
| problem | uid、k、n_nodes、v0、final |
| tool | n_tool、工具顺序 |
| var | group_id、变量→名词映射 |
| figure | **var、value（完整 float64）、text、style、font_size** |

**落盘：`history/trial/seeds_<时间戳>.jsonl`，只增不改。**

**⭐ 已验证：从台账记录能逐字节重建图片（SHA-256 一致）。**

**⚠️ 图形来源的通用性依据见
[`_参考文献\图形标准\图形来源的通用性依据.md`](_参考文献/图形标准/图形来源的通用性依据.md) §6。**

### 1.3 【结论】每次实测的数字 —— 必存

**⭐ 数字必须和它的条件绑在一起存。**

**❌ 错误写法：**

```
k=2 通过率 100%
```

**✅ 正确写法：**

```
k=2 通过率 100%
条件：每档 40 条随机链 · 池 59 个包 · 纯随机组链（不经符号前筛）
种子：k*7+1
脚本：test_any_k.py
时间：2026-11-06 23:59
```

**⭐ 落盘位置：**

- **汇总数字** → 开发日志对应小节
- **逐条明细** → `基准\logs\*.jsonl`
- **论文要引用的** → `程序设计与实现说明.md` §十 实测结果

### 1.4 【结论】设计决策与理由 —— 必存

**⭐ 决策本身不值钱，代价才值钱。**

每次定下一个规则，必须同时存：

| 项 | 例 |
|---|---|
| **定了什么** | 「cn 只取 10 的整数次幂」 |
| **谁定的、什么时候** | 研究者，2026-11-06 23:14 |
| **为什么** | 连续指数实测平均下降，且题面变丑 |
| **否掉的方案** | 连续 `10^n`（n 实数）—— 实测 k=3 从 100% 掉到 88% |
| **代价** | 一些边界情形微调不了 |

**⭐ 落盘位置：`开发日志\D<日期>_<主题>.md`**

**⚠️ 被推翻的结论不删，加删除线保留。**
理由：**只展示正确的部分，比不展示更不诚实。**

### 1.5 【结论】错误与返工 —— 必存

**⭐ 每条错误记四样：**

```
① 错了什么
② 怎么发现的
③ 代价是什么
④ 最终怎么改的
```

**⭐ 已有的例子（`D2026-11-06_骨架层与逐层系数.md` §4.12）：**

> ~~「tanh 输出上限 0.9949，ellipe 输入下限 1.0492，这条链永不存在。」~~
>
> **推翻它的证据：ellipe 的输入下限是 search[0]=0.01，不是 y_range[0]=1.049。**

**⚠️ 「把 y_range 当输入区间」这个错误当天犯了两次**，
所以单独留档 —— **同一个概念错误会换个函数再犯一次。**

### 1.6 【状态】当前进度与下一步 —— 必存

| 项 | 位置 |
|---|---|
| **做完的** | `00_待办.md`（标 ✅，不删行） |
| **没做的** | `00_待办.md`（标 🔴） |
| **卡在谁手里的** | `00_待办.md` D 类 |
| **未组装的部分** | `程序设计与实现说明.md` §十一 |

**⚠️ 硬性要求：**

- **做完的标 ✅ 不删行**（留痕）
- **未实现的必须写明「未实现」**
- **设计意图 ≠ 实现事实，必须分开写**

**⭐ 昨天的例子：**

```
「四核八线程」→ 写为「设计约束」，不是「已实现」
CUDA 为什么没跑起来 → 只记原话，标注「未经复现确认」
```

## 二、⭐ 什么不用存

**⭐ 判据：能不能重算。**

| 不用存 | 理由 |
|---|---|
| 依赖库的源码 | `pip install` 能装回来 |
| 中间张量的临时值 | 有种子和参数就能重算 |
| 大模型的原始输出 | 日志里有摘要 |
| 已被取代的旧版代码 | 移 `_backup_<日期>\`，不删 |

**⚠️ 「已被取代」不等于「可以删」。** 先移备份目录，确认没人引用再删。

## 三、⭐ 每次跑测试的保存动作（照着做）

**跑之前：**

```
□ 确认脚本固定了种子（不用 hash() / time() 做种子）
□ 确认日志路径，文件名带时间戳
□ 确认这次要存的参数齐了（种子 / n / 链 / 系数 / 窗口 / 容差）
```

**跑之后：**

```
□ 日志文件已写入 基准\logs\
□ 汇总数字写进开发日志（附条件 + 种子 + 脚本名）
□ 和上次的数字对比，变了要解释为什么
□ 如果推翻了旧结论，旧结论加删除线保留，不删
```

**改代码之后：**

```
□ 改了什么、为什么改 → 开发日志
□ 如果改了数字 → 重新生成 工具表.md / 工具分类与标记.md
□ 如果改了结构 → 更新 README 文件地图
□ 如果改了设计 → 更新 程序设计与实现说明.md
```

## 四、⭐ 文件名与目录约定

### 4.1 目录

```
<BENCH>\
├── 基准\
│   ├── generator\          代码（全部 .py）
│   ├── logs\               ⭐ 原始日志，只增不改
│   └── _backup_<日期>\     ⭐ 旧版代码，不删
└── 论文\
    └── 基准测试\
        ├── 开发日志\        ⭐ 过程：决策、错误、返工
        ├── 00_待办.md      进度
        ├── 00_总纲.md      章节规划
        ├── 程序设计与实现说明.md   ⭐ 正文级
        ├── 工具表.md        ⭐ 脚本生成
        └── 工具分类与标记.md ⭐ 脚本生成
```

### 4.2 文件名规则

| 类型 | 规则 | 例 |
|---|---|---|
| 测试日志 | `<测试名>_v<版本>_<时间戳>.jsonl` | `roundtrip_v5_20261106-213239.jsonl` |
| 样例题面 | `probe_<数量>_<日期>.txt` | `probe_100_20261106.txt` |
| 开发日志 | `D<日期>_<主题>.md` | `D2026-11-06_骨架层与逐层系数.md` |
| 备份 | `_backup_<日期>\` | `_backup_20261106\` |

**⚠️ 时间戳格式统一 `YYYYMMDD-HHMMSS`，不要用中文或空格。**

## 五、⭐ 日志条目必须含的字段

**以 `roundtrip_v5_*.jsonl` 为例（已实现）：**

```json
{
  "type": "round",              ← 事件类型
  "round": 1,
  "ok": true,                   ← 这一轮过没过
  "n": 10, "n_ok": 10,          ← 样本数与通过数
  "med_err": 1.21e-16,          ← 中位误差
  "max_err": 8.37e-16,          ← 最大误差
  "chain": {                    ← ⭐ 链的组成
    "names": [...], "codes": [...],
    "coefs": [...], "coef_codes": [...]   ← ⭐ 每步系数
  },
  "y_window": [...],            ← ⭐ y 的取值范围
  "y_vals": [...],              ← ⭐ 实际用的 y
  "x_vals": [...],              ← 算出来的 x
  "y2_vals": [...],             ← 反算回来的 y
  "t_inv_ms": 25.24,            ← 耗时
  "t_fwd_ms": 24.86,
  "reason": ""
}
```

**⚠️ 待补两个字段：**

| 字段 | 为什么 |
|---|---|
| `seed` | 现在没记种子，日志没法独立复现 |
| `tol` | 现在没记容差，判定线变了数字不可比 |

## 六、⭐ 引用数字时的规矩

**⭐ 论文里每引用一个数字，三样必须齐：**

```
① 数字本身
② 出处（脚本名）
③ 条件（n / 池大小 / 种子 / 时间）
```

**示例：**

> k=2 时随机组链的反推成功率为 100%（200/200）。
> 条件：池为 59 个可进链的包，纯随机组链不经符号前筛，
> 种子 20261107，脚本 `test_any_k.py`，2026-11-07。

**⚠️ 不许写「大约」「应该是」这类数 —— 要么实测过，要么标「未测」。**

## 七、新增内容时的检查

**在往基准测试目录加任何东西之前，先问三句：**

```
① 这是「过程」还是「结论」？
   过程 → 开发日志\        结论 → 正文级文档

② 这是「人写的」还是「脚本生成」的？
   人写的 → 可以手改
   脚本生成 → 文件名下必须写「勿手改」，改源头重跑

③ 这是「已实现」还是「设计意图」？
   已实现 → 可以写数字
   设计意图 → 必须标「未实现」
```
